# 提示词安全与评估

<p style="text-align:center;"><img src="./assets/psec-logo.png" style="zoom:75%;" /></p>

提示词安全与评估解决的是同一个问题：**大模型应用上线后，「模型行为」本身成了随时可能被利用的攻击面，而它的变更（提示词、模型、参数）没有任何编译器或类型系统帮你把关**。本专题讲清楚提示词层面攻防的完整闭环——注入为什么无法根治只能收敛、纵深防御五层怎么落、红队怎么打、评估集怎么建、变更怎么设门禁，并用「博客平台评论审核 + 文章摘要」两个真实场景做一次完整实战。

::: tip 一句话理解
传统安全的思路是「找到漏洞 → 打补丁」；提示词安全没有补丁可打——注入利用的是「指令和数据走同一条通道」这个设计事实，你只能**收敛损害**（防护工程）+ **持续验证**（评估集与回归门禁），把「模型行为」当成需要测试和监督的活体来管理。
:::

## 成熟度自评：你在哪一档

| 档位 | 特征 | 下一步 |
| --- | --- | --- |
| L0 无防护 | 只在系统提示词里写了几句「不要做 X」 | 先做[可达性自评](./Overview/index.md)，再按四问收敛权限 |
| L1 有边界 | 权限已收敛、输出只进白名单字段、渲染按不可信内容处理 | 建 L2 安全评估集（30 条起步），把边界变成断言 |
| L2 可回归 | 评估集接入 CI，红线 0 违规 | 补一轮红队摸底（garak），把发现沉淀成 L3 |
| L3 可对抗 | 有 L3 对抗层与可复跑的基线数值 | 加 L4 哨兵，防供应商静默升级 |
| L4 可持续 | 分层门禁 + 定时漂移检测 + 变更评审流程 | 保持，并每季度复核威胁模型 |

五档之间的差别不是「做了什么」，而是**「能不能证明它还在生效」**——这也是本专题与「写几句安全提示词」的根本区别。

## 学习路径

1. **先读[概述](./Overview/index.md)**：确认你的应用里哪些 OWASP 风险是「真实可达」的——清单不是挨个执行的检查表，可达性决定优先级。
2. **精读[提示注入](./Injection/index.md)**：注入占了这个领域 80% 的实际风险，直接与间接两条通道都要过一遍。
3. **按[防护工程](./Defense/index.md)自检**：五层里你至少要有「应用层」那一层——它是不依赖模型听话的唯一硬边界。
4. **走一遍[红队流程](./RedTeam/index.md)**：用 garak 对自己的端点跑一轮探针，第一手体感比十篇文章有用。
5. **建评估集、上门禁**（[EvalSet](./EvalSet/index.md) → [RegressionGate](./RegressionGate/index.md)）：这是让防护「持续有效」的机制，红队的发现全部沉淀在这里。
6. **对照[实战](./Practice/index.md)落一个真实场景**，再通读[常见问题](./FAQ/index.md)收尾。

## 与企业知识库落地的分工（第 138 天补充）

本专题处理的是「**模型被诱导做不该做的事**」——提示词注入、越狱、构造的对抗样本。而企业内部知识库面对的是一个**更朴素、也更致命**的问题：**内容根本不该出现在上下文里**。两者不重叠，也不能互相替代。

| 维度 | 本专题 | 企业知识库落地 |
| --- | --- | --- |
| 威胁来源 | 攻击者**构造**的输入（对抗样本、注入载荷） | **系统自己的语料**（权限没施加、同步没跟上） |
| 防线位置 | 提示词、输入过滤、输出检测 | **检索查询本身**（过滤条件） |
| 失败表现 | 模型说了不该说的话 | 模型**忠实地复述**了它无权阅读的原文 |
| 判据形态 | 红线 0 容忍 + 分层阈值 | 布尔：越权召回恒为 0 |

::: danger 「在提示词里写上不要泄露其他部门的内容」不是权限控制
这是本专题与本专题邻域之间最常见的一次误用。理由与提示词是否写得好无关，而在于：**只要那段文字进入了上下文，泄露就已经发生了**——模型只是最后一道概率性的闸门。

同理，「生成之后再检查答案有没有敏感词」也不成立：模型会**概括、引用、推理**，而且**「已删除某段内容」本身就是一条信息**（存在性泄露）。

正确的位置只有一个：**在检索查询里就把它排除掉**，见 [权限隔离](../EnterpriseKB/AccessControl/index.md)。
:::

## 与「AI 安全与合规」专题的分工（第 146 天补充）

本专题处理的是**「有人想让它做不该做的事」**——载荷是构造出来的，对手是一个人（或一段脚本）。而组织级治理处理的是**「没人想害你，但系统自己在违规」**：日志里躺着一串身份证号、一张图被误杀、一条该升级的请求被直接放行了。两者的输入不同，所以**评估集不同、阈值不同、判据形态也不同**。

| 边界问题 | 归本专题 | 归 [AI 安全与合规](../AISecurityCompliance/index.md) |
| --- | --- | --- |
| 输入侧 | 构造注入载荷、越狱模板、评估集与红队 | 生产流量的[双向审核](../AISecurityCompliance/ContentSafety/index.md)：法规口径 → 工程标签 → 判定规则 → 处置动作四层映射 |
| 敏感数据 | —— | [数据最小化](../AISecurityCompliance/DataMinimization/index.md)：字段白名单、三档识别与五种降级、出域复查 |
| 输出侧 | 提示词与上下文这一层的输出检测、评测集与回归门禁 | 拦截线 / 升级线**两条阈值**与「既不放行也不拦截」的第三态 |
| 工具与动作 | [Agent 安全边界](../Agent/Safety/index.md) 讲**怎么设计**不越权的 Agent | [护栏工程](../AISecurityCompliance/Guardrails/index.md)：五层闸门的执行，以及四种**静默失效**的排查顺序 |
| 证据与留痕 | 评估报告作为发布门禁的证据 | [审计链](../AISecurityCompliance/Audit/index.md)：八字段、哈希链与**截断盲区**、留存期三来源取最大 |
| 法规口径 | 不涉及 | [合规清单](../AISecurityCompliance/Compliance/index.md)：三道筛、法规地图、六格证据包 |
| 判据形态 | 对抗样本上的**红线 0 容忍** + 分层阈值 | 生产流量上的**布尔闸门**：拆掉任一道，必须看得出系统变了 |

**一句话分工**：本专题回答「**模型会不会被带偏**」；那边回答「**系统准不准它知道、准不准它说出去、说出去之后查不查得到**」。

::: warning 两套阈值不可互换（本页与那边最容易混的一处）
把「越狱成功率必须为 0」搬到生产流量上 → 误杀把真实用户挡掉；把「升级线按分位数调」搬到对抗样本上 → 攻击者只要落在分位数内就永远不被拦。

那边的**第三态判据**写的正是这件事：**存在一个非空区间，落在区间里的样本既不被放行、也不被直接拦截，而是被升级**（编号与验证方法见 [内容安全](../AISecurityCompliance/ContentSafety/index.md) 的判据定义表）——这个「第三态」在本专题的评估集里**不存在**，因为对抗样本的正确答案只有「拦」与「不拦」。
:::
