# 技能（Skills）

技能是 OpenClaw 给智能体预置的「能力包」：把一组工具、提示词和流程打包，让 Agent 在特定场景下开箱即用。

::: info 适用版本
技能体系以 OpenClaw 当前文档为准；自定义技能时注意与工具（Tools）的分工。
:::

## 技能与工具的区别

| 概念 | 定义 | 例子 |
| --- | --- | --- |
| 工具（Tools） | 单个可执行能力 | 执行命令、读写文件、网页搜索 |
| 技能（Skills） | 面向场景的能力组合 | 「运维排障」「写周报」「数据报表」 |

技能可以理解为「工具 + 系统提示词 + 工作流」的打包，降低 Agent 在特定任务上的试错成本。

## 内置技能示例

OpenClaw 常内置以下类型技能：

- 信息检索：网页搜索、文档读取。
- 文件处理：读写、格式转换。
- 开发辅助：执行命令、分析代码、写测试。
- 日常办公：写邮件、整理周报、翻译。

## 技能与工作流的关系

技能比单次工具调用更「大」，比完整工作流更「小」：

| 层级 | 粒度 | 例子 |
| --- | --- | --- |
| 工具（Tools） | 单个动作 | 执行一条命令 |
| 技能（Skills） | 一组动作的组合 | 磁盘排查：df → du → 给出清理建议 |
| 工作流（Workflow） | 跨多轮/多系统的编排 | 发布流程：测试 → 构建 → 部署 → 通知 |

设计技能时先想清楚边界：能用一个工具解决的不要做成技能，需要跨系统编排的交给工作流。

## 技能如何被调用

Agent 根据用户意图选择合适的技能：

```text
用户：帮我检查这台服务器的磁盘占用
  → Agent 选择「运维排障」技能
  → 技能内部按顺序调用工具：df、du、清理建议
```

技能内部可以定义：

1. 触发条件（什么场景使用该技能）。
2. 执行步骤（先做什么、后做什么）。
3. 依赖的工具列表。
4. 输出格式（报告、表格、摘要）。

## 自定义技能

自定义技能通常需要提供：

```text
skills/
├─ my-skill/
│  ├─ SKILL.md        # 技能说明：用途、步骤、注意事项
│  └─ scripts/        # 可选：辅助脚本
```

编写要点：

- 明确「什么时候用、什么时候不用」。
- 步骤可执行、可验证。
- 危险操作要有前置确认。
- 引用官方文档或权威来源，避免幻觉。

一个简洁的 `SKILL.md` 骨架（概念示意）：

```markdown [SKILL.md]
# 磁盘排查

当用户提到磁盘占用、空间不足、清理磁盘时使用本技能。

## 步骤
1. 执行 `df -h` 查看整体占用。
2. 执行 `du -sh /* 2>/dev/null | sort -rh | head -20` 定位大目录。
3. 给出清理建议，删除前必须向用户确认。

## 注意事项
- 不要删除正在运行的进程文件。
- 只读分析不需要确认；删除操作必须确认。
```

## 技能维护

- 技能内容随工具/平台变化更新，定期巡检。
- 记录技能使用效果（成功/失败），持续迭代提示词。
- 大技能拆成多个小技能，避免一个技能做太多事。

## 易错点

::: danger 常见错误
1. 技能描述含糊，Agent 不知道该在什么场景调用。
2. 技能里写了危险命令但没加确认步骤，误删文件。
3. 把技能当成工具，给单个命令也建技能，管理成本高。
4. 技能脚本没有错误处理，失败后 Agent 无法继续。
5. 技能内容过期（命令、API 已变），需要定期维护。
6. 技能步骤里没有「危险操作先确认」，产生不可逆操作。
:::

## 验证方式

1. 用技能对应的场景话术触发，确认 Agent 选择该技能。
2. 检查技能执行步骤是否完整走通。
3. 故意给一个不匹配的请求，确认 Agent 不会误用技能。
4. 查看日志确认技能内部工具调用顺序正确。
5. 修改技能描述后重新触发，确认新描述生效。
6. 用只读请求测试，确认没有触发未授权的删除操作。
