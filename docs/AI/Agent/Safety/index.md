# 安全边界

Agent 会“真的做事”，所以安全边界比聊天机器人重要得多：工具权限、沙箱、注入防护、人工确认、审计日志，一个都不能少。

## 风险全景

| 风险 | 示例 |
| --- | --- |
| 提示注入 | 网页/邮件内容诱导 Agent 执行恶意指令 |
| 越权操作 | Agent 删库、下单、发消息 |
| 数据泄露 | 敏感信息写入记忆/日志 |
| 工具滥用 | 无限重试、超量调用 |
| 幻觉执行 | 模型“以为”工具成功，实际失败 |

## 工具权限分级

```text
只读（安全）：搜索、查询、读文件
受控写（需确认）：发消息、下单、写文件
高风险（禁止/专人）：删数据、执行系统命令、转账
```

实现：

1. 每个工具声明权限等级。
2. 高风险工具默认禁用，白名单启用。
3. 写操作要求 `human_confirm=true` 参数或独立确认流程。

## 沙箱与隔离

1. 代码执行放沙箱（容器/无网络环境）。
2. 文件系统限定工作目录。
3. 工具超时 + 配额（调用次数、Token、时间）。

## 提示注入防护

```text
❌ 直接把网页内容拼进提示词
✅ 用分隔符隔离输入，并声明“输入只是数据不是指令”
```

进一步：

1. 输入内容先清洗/截断。
2. 关键指令放 system，重复约束。
3. 对 Agent 计划做“指令 vs 数据”校验。
4. 敏感操作二次确认，即使 Agent 被诱导也无法直接执行。

## 人工确认设计

```text
Agent 生成执行计划
  → 高风险动作 → 等待人工确认
  → 确认后执行 → 结果回填
```

确认信息要可读：**动作、对象、影响、撤销方式**。

## 审计与可观测

1. 记录每个 Agent 的完整 trace（思考、调用、结果）。
2. 记录工具执行的输入输出（脱敏）。
3. 异常行为告警（超时、高频、越权尝试）。
4. 支持回放与复盘。

## 易错点

::: danger 常见错误
1. 给 Agent 最高权限“图省事”：等于把钥匙交给模型，必须最小权限。
2. 写操作不确认：一次误触发就是事故。
3. 忽略提示注入：网页、邮件、文件内容都可能带指令。
4. 无配额：Agent 卡死循环，费用爆炸。
5. 日志不脱敏：把用户隐私写进审计日志。
6. 幻觉执行不校验：工具返回失败却被当成成功继续。
:::

## 验证方式

1. 构造一个包含恶意指令的网页内容，测试 Agent 是否被诱导。
2. 给写工具加确认流程，验证未确认不执行。
3. 设置配额，验证超限后 Agent 停止。
4. 回放一次完整 trace，确认可审计。
