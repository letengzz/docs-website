# 常见问题与最佳实践

这一篇汇总 Agent 应用高频问题与团队实践，覆盖架构、工具、记忆、安全与成本。

## 常见问题

### 1. 什么时候该用 Agent

任务需要“多步 + 工具 + 条件决策”时用 Agent；纯问答/检索用 RAG 就够。先问：没有 Agent 能不能实现？

### 2. Agent 一直循环不停怎么办

设 `max_steps`（如 5~10）、任务超时、预算上限；让模型在完成时输出明确终止标志。

### 3. 工具调用总是选错

优化工具描述：名称动词化、描述写清“何时用/何时不用”、参数给枚举与示例、减少工具数量。

### 4. 多步任务结果错乱

把关键中间结果写入显式状态，不依赖模型记忆；每步校验，错误及早终止。

### 5. 幻觉导致执行错误动作

工具执行前校验参数；高风险动作人工确认；Agent 声称成功时用工具结果交叉验证。

### 6. 上下文不够用

摘要 + 滑动窗口 + 检索注入（RAG）；中间结果精简后再回填。

### 7. 多 Agent 成本太高

先单 Agent；确需多 Agent 时共享上下文、串行改并行、减少不必要的互相评审轮数。

### 8. 怎么评估 Agent

任务成功率、工具调用正确率、步数/耗时、Token 成本、转人工率、安全事件数；建黄金集回归。

### 9. 如何防提示注入

输入与指令分离（分隔符）、system 强约束、敏感操作二次确认、输入清洗截断、工具权限最小化。

### 10. 上线前必须做什么

权限与确认、配额与超时、完整 trace、脱敏日志、黄金集评估、转人工兜底、灰度与回滚。

## 最佳实践清单

::: tip 可直接落地的清单
1. 最小可行 Agent：先单 Agent + 少量工具跑通价值。
2. 工具描述写清楚，按场景分组。
3. 状态显式化，中间结果存 store。
4. 最大步数 + 超时 + 预算三重上限。
5. 只读自动化，写操作人工确认。
6. 记忆按用户隔离、脱敏、可删除。
7. 完整 trace 与脱敏审计日志。
8. 黄金集回归，失败样本回流。
9. 转人工兜底，Agent 失败不裸奔。
10. 灰度发布，指标对比后再全量。
:::

## 验证方式

1. 用 FAQ 10 问做一轮自查。
2. 跑一次“故障注入”演练（工具失败、注入、超时）。
3. 上线后建立周报：成功率、成本、安全事件。
