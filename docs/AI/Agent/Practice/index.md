# 落地案例

从想法到生产，Agent 应用要过“原型 → 工程化 → 上线 → 迭代”四关。这一篇给出 4 个常见场景和一套落地清单。

## 场景一：智能客服

```text
用户问题 → 意图识别 → 检索知识库（RAG）→ 生成回答 → 兜底转人工
```

关键点：

1. 知识库检索质量决定上限。
2. 不确定时明确说“不知道”并转人工。
3. 写操作（改单）走人工确认。

## 场景二：代码助手

```text
任务描述 → 读取代码库 → 生成方案 → 生成补丁 → 测试 → 提交建议
```

关键点：

1. 只读分析 + 生成建议，不直接推送。
2. 工具权限：读仓库 ✓，写仓库 ✗（出 PR 建议）。
3. 沙箱运行测试。

## 场景三：数据查询助手

```text
自然语言 → 生成 SQL → 只读执行 → 校验结果 → 回答
```

关键点：

1. 数据库账号**只读**。
2. SQL 白名单/黑名单校验。
3. 限制扫描行数与执行时间。
4. 高风险语句（DROP/DELETE）直接拒绝。

## 场景四：自动化运维

```text
告警 → Agent 诊断（查日志/指标）→ 生成处置建议 → 人工确认执行
```

关键点：

1. 先“建议”后“执行”。
2. 只读诊断自动化，变更操作人工确认。
3. 完整审计 trace。

## 从原型到生产

```text
1. 验证价值：最小原型跑通核心循环
2. 工程化：工具封装、错误处理、超时重试
3. 可观测：trace、日志、指标
4. 安全：权限、确认、配额、审计
5. 上线：灰度、评估、回滚
6. 迭代：失败样本回流黄金集
```

## 落地检查清单

::: tip 可直接落地的清单
1. 明确任务边界：什么该 Agent 做、什么不做。
2. 工具最小权限，写操作人工确认。
3. 设置最大步数与预算上限。
4. 完整 trace + 脱敏日志。
5. 黄金集评估 + 回归测试。
6. 失败兜底：转人工、默认安全回答。
7. 灰度发布与回滚方案。
8. 成本监控：Token、调用次数、延迟。
:::

## 易错点

::: danger 常见错误
1. 原型直接上线：没有权限、配额、评估，事故率极高。
2. 场景选错：高频、强流程任务才值得 Agent，纯问答用 RAG 即可。
3. 评估只看 demo 效果：上线前跑黄金集与压测。
4. 忽略转人工路径：Agent 失败时用户没人接管。
5. 一次性铺开所有场景：先一个场景跑通再复制。
:::

## 验证方式

1. 选一个场景跑通端到端原型。
2. 按落地清单逐项自检。
3. 上线后监控：成功率、转人工率、成本、用户反馈。
