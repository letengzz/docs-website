# 提示词模板库

提示词工程化落地 = **模板化 + 版本管理 + 团队复用**。把高频任务沉淀成模板，用变量注入业务数据，配合测试与版本管理，让提示词像代码一样可维护。

## 模板结构

```text
系统提示词（固定）
  + 任务说明（固定）
  + 变量区（{{input}}、{{context}}）
  + 输出要求（固定）
```

示例模板：

```text
你是{{role}}。
任务：{{task}}。
背景：{{context}}。
输入：
<input>
{{input}}
</input>
输出要求：{{output_format}}
```

## 变量化

```python [prompt.py]
prompt = f"""
你是{role}。
请把以下内容翻译成{target_lang}：
<input>{text}</input>
只输出译文。
"""
```

好处：

1. 同一模板复用不同角色/语言/输入。
2. 与业务代码解耦。
3. 便于 A/B 与回归测试。

## 模板分类

| 分类 | 模板示例 |
| --- | --- |
| 代码类 | 代码审查、SQL 生成、错误解释 |
| 内容类 | 翻译、改写、总结、标题生成 |
| 数据类 | 信息抽取、分类、JSON 转换 |
| 对话类 | 客服、角色扮演、多轮问答 |

## 版本管理

1. 模板用 Git 管理，记录变更历史。
2. 每次改动标注版本号与效果指标。
3. 线上模板与测试模板分离，灰度发布。

```text
v1.0：初版
v1.1：增加 JSON 格式约束（解析成功率 82% → 96%）
v1.2：加入 few-shot 示例（准确率 +5%）
```

## 工程化实践

```text
Prompt 仓库（Git）
├── templates/           # 模板文件
├── tests/               # 黄金集与断言
├── prompts.py           # 加载与渲染
└── CHANGELOG.md         # 版本与效果记录
```

配合流程：

1. 模板评审（角色/边界/安全）。
2. 黄金集回归测试。
3. 灰度发布与指标对比。

## 易错点

::: danger 常见错误
1. 模板硬编码在业务代码里：改一个词都要发版，应抽离配置。
2. 变量直接拼入指令：注意转义与提示注入。
3. 没有版本记录：效果变差无法回滚。
4. 模板“一个打天下”：不同任务共用一份，互相妥协。
5. 只建模板不做测试：模板库沦为文档。
6. 敏感信息留在模板日志里：脱敏后再记录。
:::

## 验证方式

1. 把团队 3 个高频任务沉淀为模板并变量化。
2. 用黄金集对模板做回归测试，记录指标。
3. 模板改版后对比 v1/v2 的效果数据。
