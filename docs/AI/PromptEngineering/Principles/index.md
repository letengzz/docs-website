# 原理与模型行为

要写好提示词，先理解大模型（LLM）是怎么工作的：它本质是“根据上文预测下一个 Token”的模型，提示词就是它的“上文”。理解 Token、温度、上下文窗口与幻觉，才能解释为什么同样的话输出不一样。

## 大模型如何理解提示词

```text
用户提示词 → Token 化（分词）→ 模型逐 Token 生成 → 输出文本
```

1. 文本先被切分成 **Token**（约 1 个英文单词 ≈ 1~2 Token，1 个汉字 ≈ 1~2 Token）。
2. 模型按概率生成下一个 Token，而不是“查答案”。
3. 所以提示词越清晰、越具体，模型“猜对”的概率越高。

## 关键参数

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `temperature` | 随机性：越高越发散 | 事实任务 0~0.3，创意任务 0.7~1.0 |
| `top_p` | 核采样：候选 Token 概率累计阈值 | 与 temperature 二选一调 |
| `max_tokens` | 最大输出长度 | 按任务预估 |
| `presence_penalty` | 鼓励讨论新话题 | 内容生成可调 |
| `stop` | 停止符 | 结构化输出用 |

## 上下文窗口

每个模型有最大上下文（如 8K、32K、128K+ Token）。超长输入会被截断或报错，处理长文档要：

1. 截断/分段。
2. 摘要后注入。
3. 检索相关片段（RAG）。

## 指令遵循与幻觉

- **指令遵循**：模型按 prompt 里的要求执行，但要求含糊时会“自由发挥”。
- **幻觉（Hallucination）**：模型编造看似合理的内容。缓解：要求“不确定就说不确定”、给依据、加 few-shot 示例、降低温度。

```text
❌ 给我讲讲这个产品
✅ 你是产品经理，用 3 句话介绍这个产品的定位，不确定的信息标注「待核实」
```

## 为什么提示词有效

1. **引导生成分布**：明确的格式与示例让模型更容易生成期望内容。
2. **利用先验知识**：模型训练过大量文本，好的角色设定能激活对应知识。
3. **减少歧义**：上下文越完整，生成越稳定。

## 易错点

::: danger 常见错误
1. 一次问太多问题：输出“大杂烩”，拆成多个子任务。
2. 不设输出格式：解析困难，要求列表/JSON 时给出格式。
3. 温度一律默认：事实问答用高温会导致答案飘忽。
4. 忽略上下文上限：长文档截断后结果残缺。
5. 把幻觉当“bug”：它是模型特性，要用提示词和验证机制缓解。
6. 用 `max_tokens` 当上下文长度：它限制输出，不是输入。
:::

## 验证方式

1. 用同一提示词调低/调高 temperature 各跑 5 次，观察稳定性差异。
2. 统计不同提示词版本在固定测试集上的成功率。
3. 故意给模糊指令与结构化指令，对比输出差异。
