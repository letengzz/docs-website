# 常见问题与最佳实践

这一篇汇总提示词工程高频问题与团队实践，覆盖稳定性、幻觉、格式、上下文与成本。

## 常见问题

### 1. 输出不稳定怎么办

1. 降低 `temperature`（0~0.3）。
2. 结构化提示词 + 输出格式约束。
3. 加 few-shot 示例固定格式。
4. 关键任务做多路采样取多数票。

### 2. 模型幻觉怎么缓解

1. 要求“不确定就说不知道”。
2. 提供参考资料并要求基于资料回答（RAG）。
3. 降低温度，加边界示例。
4. 下游加事实校验。

### 3. 输出的 JSON 总是解析失败

1. 给出精确 JSON schema 示例。
2. 要求“只输出 JSON，不要代码块标记”。
3. 解析失败自动重试一次。
4. 考虑用结构化输出（JSON mode / Function Calling）。

### 4. 上下文超限怎么办

截断、摘要、滑动窗口、RAG 检索相关片段；不要盲目加大窗口（成本与延迟上升）。

### 5. 什么是提示注入

用户输入里夹带指令，诱导模型执行非预期操作。缓解：分隔符隔离、system 约束、输入校验、敏感操作二次确认。

### 6. temperature 和 top_p 怎么调

事实/抽取任务：temperature 0~0.3；创意任务：0.7~1.0。二者通常只调一个，避免叠加随机性。

### 7. few-shot 加了很多示例还是不准

检查示例是否覆盖真实输入分布、格式是否一致、是否包含边界情况；示例质量比数量更重要。

### 8. 如何评估提示词好坏

建黄金集 + 规则/LLM-judge 评估 + 指标对比；线上失败样本回流到评估集，持续迭代。

### 9. 提示词工程要投入多少成本

先评估业务收益：低风险高频任务先模板化；每次改版做回归；用缓存与批处理控制成本。

### 10. 什么时候该用 Agent/工具而不是纯提示词

需要实时数据、计算、多步操作时，用工具调用/Agent；纯提示词适合单步、无外部依赖的任务。

## 最佳实践清单

::: tip 可直接落地的清单
1. 提示词六要素：角色、任务、背景、输入、输出要求、示例。
2. 指令与输入用分隔符隔离，防注入。
3. 事实任务低温，创意任务高温。
4. 关键输出给 JSON schema 并要求只输出 JSON。
5. 数学/逻辑任务用思维链，必要时 Self-Consistency。
6. 高频任务沉淀模板库，Git 管理版本。
7. 建立黄金集与回归测试，改版必须对比指标。
8. 长对话用摘要/检索管理上下文。
9. 模型不确定时允许说“不知道”，减少幻觉。
10. 关注成本：Token、延迟、调用次数，能缓存就缓存。
:::

## 验证方式

1. 用 FAQ 的 10 个问题各写一个最小实验验证。
2. 建立团队的提示词模板仓库与黄金集。
3. 对一次改版做完整回归，记录指标变化。
