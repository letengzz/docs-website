# 常见问题与分诊

P2P 故障的特点是**跨三个部门、四个系统**：采购说单下了，仓库说没到，财务说票开了，出纳说付了。一句「这笔钱不对」可以指向二十个地方。本页给一张分诊表，把一句模糊的话变成一条可执行的查询。

::: tip 一句话定位
分诊的第一问永远是：**问题落在四个时点的哪两个之间**。落在「承诺 → 实物」是采购与仓库；落在「实物 → 账」是收货与财务；落在「账 → 钱」是财务与出纳。定出这两个部门，范围立刻砍掉三分之二。
:::

本页判据族 `PTQ-A` ~ `PTQ-H`，共 8 条。定义表在第六节。

## 一、八行分诊表

| 现象 | 先看什么 | 查询 | 常见结论 |
| --- | --- | --- | --- |
| 预算没用完却提不了单 | `budget.used_amount` 与流水 | `SELECT ref_type,ref_no,delta FROM budget_txn WHERE budget_id=?` | 有申请驳回未释放，或订单关闭未释放 |
| 仓库说收了、财务说没暂估 | `gr_line.qc_state` | `SELECT qc_state,count(*) FROM gr_line WHERE po_no=? GROUP BY 1` | 全部 `PENDING`：待检没判，不算可匹配 |
| 供应商说少收了 | 订单版本与累计收货 | `SELECT po_version,sum(qty) FROM gr_line WHERE po_no=? GROUP BY 1` | 收货记在 v1，订单已改 v2，基准算错 |
| 发票一直被拒 | `match_result.diff_type` | `SELECT diff_type,diff_amount FROM match_result WHERE invoice_id=?` | `PRICE`：单价不符；`QTY`：超过可匹配量 |
| 同一张发票显示付了两次 | `payment_item` 唯一键 | `SELECT batch_id,payment_no,amount FROM payment_item WHERE invoice_id=?` | 若真有两行，说明唯一索引缺失或被绕过 |
| 付款发了但供应商没收到 | 批次状态与回单 | `SELECT state,return_reason FROM payment_item WHERE batch_id=?` | 停在 `SENT`：银行未受理；`RETURNED`：账户/户名不符 |
| 月度报表「暂估」科目越来越大 | 未开票收货 | `SELECT sum(qty*unit_price) FROM gr_line WHERE po_no NOT IN (SELECT po_no FROM ap_invoice_line)` | 收货开了票但没匹配，或供应商压票 |
| 折扣从来没拿到过 | 账期与批次日期 | `SELECT invoice_date,run_date FROM ap_invoice i JOIN payment_item p ON p.invoice_id=i.invoice_id JOIN payment_batch b ON b.batch_id=p.batch_id` | 批次日 > 折扣截止日，排程没把窗口纳入 |

## 二、止血五步（按顺序，不要跳）

1. **定时点**。先确认问题落在哪两个时点之间（承诺/实物/账/钱），只查这两段的数据。
2. **定单据**。拿到 `po_no` + `po_version`、`gr_no`、`invoice_no`、`payment_batch_id` 四个键中的至少两个。
3. **跑不变量**。四条不变量（预算、收货上限、开票不超可匹配、付款不超开票）先跑一遍，看哪条非 0。
4. **看分类**。非 0 的差额必须落到 `PRICE/QTY/TAX/FEE` 之一；落在 `OTHER` 说明分类规则不够，先补规则再谈业务。
5. **留证**。把查询语句、结果、时间戳贴进工单——P2P 的争议最后都要靠「当时是什么数」来裁决。

## 三、十二问

**Q1：为什么不能只用订单状态表示「到货」？**
因为四个部门对「到货」的定义不同。一个复合状态会在跨部门沟通时被反复误读，且无法回答「上月在途多少」。

**Q2：预算占用为什么不能用「查余额」？**
查询与扣减之间有时间窗。本机实测 8 线程下先查后写 56 笔通过（应 50 笔），多占 6,000 元。

**Q3：订单改版后，已经收的货怎么办？**
不动历史。改版只影响未收部分；已收货的暂估按收货时点冻结的版本价保留，价差走调整单。

**Q4：超收允差该定多少？**
从「历史人工放过的差异」反推 P90，再看人工量能否承受。本机实测：允差 0% 只有 9.1% 自动通过，5% 是 89.7%。

**Q5：待检的货算不算已收？**
算「已收」（仓库口径），不算「可匹配」（财务口径）。两个数必须分开存。

**Q6：三单匹配一定要做吗？**
实物采购建议至少 3 路；服务类做 2 路。硬给服务加「收货单」只会得到一堆人造单据。

**Q7：容差 1% 还是 2%？**
看你的发票偏差分布与人工量。1% 能过 59.2%，2% 能过 90.9%——差的那 30% 就是人工成本。

**Q8：为什么一定要区分价差和税差？**
税率调整期如果不区分，所有发票都会被判价差并开扣款单，供应商不会认。

**Q9：付款批次为什么要幂等？**
重跑一次任务影响的是整批。`payment_no` 由 `(batch_id, invoice_id)` 派生，重跑得到同一编号，银行侧可直接去重。

**Q10：现金折扣怎么判断该不该拿？**
算年化：`折扣率/(1−折扣率) × 365/(账期−折扣窗口)`。2/10 net 30 是 37.2%，几乎总该拿；1/30 net 60 只有 12.3%。

**Q11：预付款怎么冲？**
发票入账时按 `prepay_id` 冲抵，累计冲抵不得超过预付金额；尾款才进付款批次。

**Q12：差异一直挂在「其他」怎么办？**
给 `OTHER` 设 30 天升级规则。没有升级机制的 `OTHER` 就是垃圾桶，半年后会占满整张表。

## 四、二十项自查

| # | 自查项 | 不满足的后果 |
| --- | --- | --- |
| 1 | 四张主表各有独立业务时间列 | 无法算在途/暂估/应付 |
| 2 | 收货行存 `po_version` | 超收算不出来 |
| 3 | `budget` 四维唯一 | 预算可重复建 |
| 4 | 占用是条件更新 | 并发超占 |
| 5 | 释放有唯一流水 | 重复释放 |
| 6 | 报价截止前接口不返回价格 | 密封失效 |
| 7 | 评分前做归一化 | 排序由量纲决定 |
| 8 | 下单校验资质有效期 | 过期供应商可下单 |
| 9 | 供应商按信用代码去重 | 重复档案、双账户付款 |
| 10 | 分批用计划行不用多行 | 行号对齐失效 |
| 11 | 数量减少校验已收+在途 | 可改到已收以下 |
| 12 | 税额按行算 | 与发票差 1 分 |
| 13 | 收货 `unit_price` 冻结 | 历史暂估被重算 |
| 14 | 可匹配量排除待检 | 暂估提前 |
| 15 | 退货用反向单 | 审计断链 |
| 16 | 容差用 `max(绝对额, 比例)` | 小额行永远不过 |
| 17 | 差异四分类各有动作 | 差额进垃圾桶 |
| 18 | 发票唯一键含 `supplier_id` | 重复入账 |
| 19 | `payment_item` 唯一约束 `invoice_id` | 一票两批 |
| 20 | 回单用 `EndToEndId` 回写 | 同额同日错配 |

## 五、术语表

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 三单匹配 | 3-way match | 订单、收货、发票三者数量与金额对齐 |
| GR/IR | Goods Receipt / Invoice Receipt | 收货已记、发票未到的暂估科目 |
| 落地成本 | landed cost | 含运费、关税、账期折现后的可比单价 |
| 允差 | tolerance | 允许的偏差范围，超出需审批 |
| 让步接收 | concession | 有瑕疵但可用的质检结论 |
| ASN | Advance Shipping Notice | 供应商的预先发货通知 |
| 付款批次 | payment run / batch | 一次付款任务的单位，幂等的基本粒度 |

## 六、判据

| 判据 | 看什么现象 | 判成什么 | 不满足时改哪里 |
| --- | --- | --- | --- |
| `PTQ-A` | 分诊表每一行是否都有可执行查询 | 只有「检查配置」这类描述即判「不可执行」 | 每行补一条 SQL 或命令 |
| `PTQ-B` | 分诊表是否按四个时点分区 | 混在一起即判「无法定位部门」 | 行首补「承诺/实物/账/钱」标签 |
| `PTQ-C` | 十二问是否都有明确结论（而非「视情况」） | 出现「视情况而定」即判「无效问答」 | 补判据与阈值，或直接删掉该问 |
| `PTQ-D` | 自查表是否覆盖四张主表与三个唯一键 | 缺一项即判「清单不全」 | 按第 4 节表项补齐 |
| `PTQ-E` | 术语表是否给出英文原文 | 只有中文即判「无法对外沟通」 | 补英文列 |
| `PTQ-F` | 分诊结论是否指向具体表或列 | 指向「系统」即判「不可操作」 | 改为 `表.列` 形式 |
| `PTQ-G` | 止血五步是否有序（定时点 → 定单据 → 跑不变量 → 看分类 → 留证） | 顺序颠倒即判「先入为主」 | 按序重写 |
| `PTQ-H` | 本页是否声明「不做什么」 | 无边界声明即判「范围蔓延」 | 补一节「本页不解决什么」 |

## 七、本页不解决什么

- **不解决 ERP 产品选型**：SAP、Oracle、金蝶、用友的模块差异属于实施范畴，本页只讲判据。
- **不解决税务合规细节**：进项抵扣、红字发票开具流程以当地税务口径为准。
- **不解决银行接口对接**：只给报文字段与回写键，具体银行的前置机、签名、证书另论。
- **不解决组织与审批文化**：审批矩阵给的是结构，阈值必须按组织实际调整。
