# 选渠道：地址、可达与运价

「发哪个快递」看起来是个听运营的问题，实际上是个**算术问题**：地址决定能不能到，尺寸重量决定计费重，计费重与分区决定价格，价格与时效承诺决定选谁。四步里有任何一步用了错的口径，选出来的渠道就会「当时看着合理、月底账单不合理」。

这一页把选渠道拆成四段可计算的步骤，并回答三个问题：**体积重为什么会赢、地址为什么归一不了、以及「最便宜的渠道」到底能不能选**。

![选渠道的四段与两个硬门槛](../assets/sc-sourcing.svg)

本页判据族 `LGS-A` ~ `LGS-H`，共 8 条。定义表在第六节。

## 一、计费重：实重、体积重与「谁说了算」

承运商按 **计费重（chargeable weight）** 收费，而不是按你称出来的重量：

```text
体积重 = 长 × 宽 × 高 ÷ 除数
计费重 = max(实重, 体积重)   （部分产品取整到 0.5kg 或 1kg）
```

除数是产品属性，不是物理常数。国内快递常见 **6000**，部分国际产品用 **5000**，英制口径里还有用 **139（in³/lb）** 的。

本机读数（20,000 件，尺寸 12~45cm、实重对数正态）：

| 除数 | 体积重胜出的比例 | 说明 |
| --- | --- | --- |
| 6000 | **62.39%** | 大多数包裹其实是「按体积收费」 |
| 5000 | **68.63%** | 除数越小，体积重越容易赢 |

按 6000 计费后，平均每件「增重」**0.702 kg**。

::: danger 注意
1. **不要只把实重传给承运商**。你报实重，它会用自己的测量值补体积重，而**复核值与申报值的差额会在账单里追收**——这就是行业里「体积重复核」类差异占大头的来源。
2. **不要用「四舍五入到整公斤」做内部估算**。多数产品是**向上取整**（进位），20.1kg 按 21kg 收。用四舍五入会系统性低估，估算越准越开心、账单越难看。
3. **不要在报价时用「估算尺寸」**。商品主数据里的尺寸常常是「包装前」的，包装后长宽高各加 2~5cm，体积重可能翻倍。**用仓内实测值，并把实测时间戳存下来**——它是日后争议的唯一证据。
:::

## 二、可达与分区：能不能到，比多少钱更早决定

可达性（serviceability）有三层，判断顺序不能颠倒：

| 层 | 判断 | 数据来源 | 失败表现 |
| --- | --- | --- | --- |
| ① 行政可达 | 省/市/区县是否在服务范围 | 承运商服务范围表 | 建单直接拒 |
| ② 产品可达 | 该产品是否覆盖该地区（如次日达只覆盖部分城市） | 产品线路表 | 建单成功，实际走慢线 |
| ③ 商品合规 | 带电/液体/粉末/冷链是否可运 | 商品属性 × 承运商限制 | 安检退回 |

第二层是最容易被跳过的：**建单成功不等于按时效到达**。次日达产品只覆盖部分城市，落到覆盖外会用「经济件」承运，客户看到的时效承诺与实际走的产品不是一回事。

分区（zone）则是价格的第三个输入：

```text
运费 = f(计费重, 分区, 产品)
分区 = g(寄件地邮编, 收件地邮编)   ← 承运商定义，不是你算的
```

::: warning 分区必须用承运商的分区表
自己按「距离」估分区在省内看起来还行，跨省必错——分区表是按分拨中心与线路划的，不是按直线距离。**这张表要定期全量替换**（承运商每年至少调一次），替换时保留版本号，否则历史账单无法复算。
:::

## 三、地址归一：为什么「去掉空格」不够

地址是自由文本，而承运商要的是结构化字段。中间这层归一，决定了多少单会被判「地址不详」。

本机读数（2,000 组同一地址的四种写法，做「去空格 + 繁简同义字替换」后比对）：

```text
与标准写法完全相等：1,002 / 2,000 = 50.10%
```

也就是说，**最朴素的归一只能覆盖一半**。剩下的一半来自这些差异：

| 差异类型 | 例子 | 归一的难点 |
| --- | --- | --- |
| 省/市后缀省略 | 「广东深圳」vs「广东省深圳市」 | 需要行政区划词典补齐 |
| 直辖市重复 | 「北京市北京市朝阳区」 | 需要去重规则 |
| 区县缺失 | 「深圳市南山区」写成「深圳南山」 | 需要别名词典 |
| 同音/形近字 | 「科技园南路」vs「科技园南璐」 | 只能模糊匹配 + 人工复核 |
| 新旧地址 | 撤县设区后的旧名 | 需要历史区划映射表 |
| 详址顺序 | 「88号科技园南路」 | 需要分段识别 |

工程上的做法是**三级**，而不是一个正则：

1. **词典级**：省市区三级标准表 + 别名词典 + 历史映射，做精确匹配。这一级能吃掉大部分。
2. **模糊级**：编辑距离 / 拼音相似度，在候选集里排序，**只用于提示，不用于自动改写**。
3. **人工级**：模糊级置信度低于阈值的单进复核队列，**复核前不建单**——因为建单后再改地址要收「地址更正费」。

::: danger 一个昂贵的偷懒
**不要「先建单、地址错了再改」**。地址更正（address correction）在多数合同里是**按票收费**的，且这笔费用通常**不与你申报的地址是否明显错误挂钩**。本机口径：一次更正的费用往往等于该票基础运费的 30%~100%。宁可建单前多花 200ms 做一次校验。
:::

## 四、询价与选渠道：最便宜的不一定能选

询价（rate shopping）返回的是一组报价，选谁要看**目标函数**：

| 目标 | 选法 | 代价 |
| --- | --- | --- |
| 成本最低 | 取 `price` 最小 | 时效可能最长，投诉率上升 |
| 时效优先 | 取 `transit_days` 最小 | 成本上升，且「快」不一定「准」 |
| 平衡 | 加权评分（成本 0.6 + 时效 0.3 + 稳定性 0.1） | 权重需要按月校准 |

本机读数（1,000 次询价，3 家承运商）：

```text
「默认承运商」不是最便宜的：652 / 1,000 = 65.2%，平均每单多付 2.98 元
「默认承运商」不是最快的：598 / 1,000 = 59.8%
```

结论不是「一定要比价」，而是：**「默认渠道」这个策略本身有成本，而它从不出现在任何报表里**。65.2% × 2.98 元 ≈ 每单 1.94 元的隐性成本，量大了就是一条独立预算线。

::: tip 三个选渠道的硬约束（比价格更优先）
1. **可达性优先**：不可达的报价直接剔除，不要靠「贵一点总能到」兜底。
2. **合同量优先**：多数合同有**最低货量承诺**，比价过度会导致承诺不达标、次年议价能力下降。把「合同量完成度」作为评分项。
3. **单点风险**：单一承运商占比 >70% 时，即使它最便宜也要分流。承运商爆仓/系统故障时，你没有第二条路。
:::

## 五、兜底与拆包

两个必须显式设计的场景：

**兜底渠道**（fallback）：主渠道不可用时，按「贵但可达」的顺序降级。降级要留痕（`fallback_reason`），否则没人知道这个月的成本为什么涨。

**拆包决策**（split）：一单可能因为体积、重量上限、商品类型（带电与不带电不能混装）拆成多个包裹。拆包一旦发生：

- 子母件关系必须落库（见[取号契约](../LabelContract/index.md) `LGL-B`）；
- 每件独立计费重，**总运费不是原单运费的拆分**（首重只算一次，但每件都有续重）；
- 客户侧要合并展示，否则「一个订单五个运单号」会被当成发错货。

## 六、本页判据

| 判据 | 看什么现象 | 判成什么 | 不满足时改哪里 |
| --- | --- | --- | --- |
| `LGS-A` | 计费重 = `max(实重, 体积重)`，体积重除数来自产品配置 | 计费重正确 | 建「产品 → 除数」配置，禁止硬编码 6000 |
| `LGS-B` | 尺寸取仓内实测值并带时间戳，不用主数据估算值 | 有据可依 | 落 `measured_at` 与测量设备编号 |
| `LGS-C` | 计费重按产品规则**向上取整** | 不低估 | 区分 `ceil` 与 `round` 两种取整产品 |
| `LGS-D` | 可达性三层（行政/产品/合规）在建单前判定 | 不可达不下单 | 把三层判断做成取号的前置守卫 |
| `LGS-E` | 分区来自承运商分区表，且有版本号 | 可复算 | 建 `zone_table(version, from_zip, to_zip, zone)` |
| `LGS-F` | 地址归一三级（词典/模糊/人工），模糊结果不改写原值 | 不误改 | 模糊匹配只打标，原值单独存 |
| `LGS-G` | 选渠道的评分包含可达性、价格、时效、合同量四项 | 策略可解释 | 把「默认渠道」换成可配置评分 |
| `LGS-H` | 兜底渠道存在且记录降级原因 | 单点可控 | 加 `fallback_reason` 与告警 |

## 七、验证方式

`LGS-A` 与 `LGS-C` 都能用一条 SQL 自查是否有「算错的口径」：

```sql
-- 1) 找出「按实重收费但其实体积重更大」的运单（口径走错的证据）
select count(*)                                             as total,
       count(*) filter (where greatest(real_kg, vol_kg) > real_kg + 0.001) as dim_wins,
       round(100.0 * count(*) filter (where greatest(real_kg, vol_kg) > real_kg + 0.001)
             / nullif(count(*), 0), 2)                      as dim_win_pct
from (
  select real_kg,
         (length_cm * width_cm * height_cm) / 6000.0 as vol_kg
  from shipment_parcel
  where measured_at >= now() - interval '7 day'
) t;
```

预期输出：`dim_win_pct` 大致落在 **60%~70%**（本机 20,000 件为 62.39%）。若显著偏低（如 <20%），说明尺寸数据大量缺失或用了包装前尺寸；若接近 100%，说明实重字段可能被写成了体积重。

```shell
# 2) 向上取整 vs 四舍五入：同一批重量两种口径的差额
python3 - <<'PY'
import math
ws = [0.4, 1.2, 3.6, 10.1, 20.5, 30.9]
ceil_sum  = sum(math.ceil(w) for w in ws)
round_sum = sum(round(w) for w in ws)
print(f"向上取整合计 {ceil_sum} kg；四舍五入合计 {round_sum} kg；差 {ceil_sum-round_sum} kg")
PY
```

预期输出：`向上取整合计 70 kg；四舍五入合计 66 kg；差 4 kg`。按 6.5 元/kg 算，这一批的估算偏差是 26 元——**估算表越准，这个偏差越不应该出现**。

```shell
# 3) 地址归一覆盖率体检（对应 LGS-F）
grep -c . addresses.csv                    # 总行数
grep -cE '^[^,]+,[^,]+,[^,]+,[^,]+$' addresses.csv   # 四级齐全的行数
```

预期输出：两级数字的比值就是「结构化完整率」。低于 95% 时，模糊级与人工级的队列会显著变长，应先补词典再上线。

## 与「采购到付款（P2P）与三单匹配工程」的分工（第 224 天补充）

| 这件事 | 本页负责 | [采购到付款专题](../../ProcureToPay/index.md) 负责 |
| --- | --- | --- |
| 寻源对象 | 运力（承运商、线路、时效） | 物资与服务（供应商、料号、价格） |
| 报价口径 | 首重续重、抛比、附加费 | 落地成本（税、运费、账期折现、质量成本） |
| 结算 | 运费账单与对账 | 采购发票的三单匹配 |
| 绩效 | 时效达成、破损率 | 准时交付率、批次合格率 |

一句话：**本页把运费算成「一条线路的价格」，P2P 把运费算成「一件货的成本」**。

::: danger 本页特有的一个坑（与 P2P 相关）
**运费不能只当独立费用，必须摊进落地成本再比价**。同一料号 A 家报 12.50 出厂价、B 家报 12.80 到厂价，只比单价会选 A，加上运费后 A 反而更贵。反过来，摊进单价之后退货时又会按「含运费单价」退，供应商不认——正确做法是：**比价时摊进去（`v_landed_cost` 视图），单据上运费单独成行**，退货只退货款，运费按合同条款另议。
:::
