# 常见问题与分诊

<p style="text-align:center;"><img src="../assets/wh-logo.png" alt="仓储作业与波次拣选" style="zoom:75%;" /></p>

仓储问题的特点是**症状出现在下游、根因留在上游**：客户说少发了，根因可能是三周前一次没收差异；拣货员说「货不在位」，根因可能是昨天一次没记账的移库。这一页给的是**分诊路径**，不是标准答案。

本页判据族 `WHQ-A` ~ `WHQ-H`，共 8 条，定义在第五节。

## 二、十二个高频问题

### 1. 库存准确率 99% 为什么还会短拣？

因为「准确率」通常是**按库位**算的：1,000 个库位里 10 个不准 = 99%。但拣货只会去**有货的库位**，而那 10 个不准的库位恰恰是「账上有、实际少」的，它们被访问的概率远高于平均值。**报准确率必须同时报「按金额」与「按访问频次加权」。**

### 2. 波次越大越省，为什么不能开到 500 单？

三个约束同时收紧：① **截单时间**——500 单要凑到晚上，早班车赶不上；② **拣货位容量**——拣货车装不下 500 单的货；③ **错误影响面**——一次拣错 500 单一起错。本机读数里 20 → 50 单只再省 6.25 个百分点，**边际收益已经很薄**。

### 3. 用 `SELECT ... FOR UPDATE` 还是条件更新？

两种都对，取舍看冲突率。冲突少（同一库位很少被并发拣）时条件更新更便宜；冲突多（爆款集中在少数库位）时 `FOR UPDATE` 能减少重试。**不要混用**：一半代码加锁、一半条件更新，等于都没做。

### 4. 盘点要不要停业？

循环盘点不需要停业，代价是「盘点期间该库位不许拣」。全面盘点才需要停业，而全面盘点的真实目的是**审计**（对外证明账实一致），不是运营改善——运营改善靠循环盘点。

### 5. 为什么 FEFO 比 FIFO 好，但很多仓还在用 FIFO？

因为 FEFO 需要**每个批次都有准确效期**，而效期数据的采集成本很高（供应商不一定给、给了不一定准）。没有可靠效期时，FEFO 会变成「按垃圾数据排序」，反而不如 FIFO。**先解决数据，再谈策略。**

### 6. 一单多包时，订单状态怎么推进？

订单状态按**最慢的那个包裹**推进：全部包裹 `HANDED_OVER` 才转「已发货」。按第一个包裹推进，会出现「订单已发货、还有一个包在仓里」。

### 7. 短拣之后应该缺量发还是整单挂起？

看品类：标品（可补发、客户不着急）缺量发；定制 / 礼品 / 时效品整单挂起。**策略要挂在 SKU 上**，不能全局一个开关——两种做法各有各的客诉。

### 8. 库位编码能不能用中文？

技术上可以，运维上是灾难：手持终端、打印机、条码枪、Excel 导入导出、跨系统对账，每一个环节都可能把中文变成乱码。**编码只用大写字母 + 数字 + 连字符。**

### 9. 为什么「就近填空」看起来最好，实际最差？

因为它把库位往门口压，短期内拣选确实省；但**扩容与退货没有位置**，而且同 SKU 会被拆到多个库位（每次补货都往最近空位放），于是拣一单要跑三个地方。本机读数里它的拣选行走 132.47 m 是最低的，但它的**同 SKU 分散度**最高，这个代价不在距离里。

### 10. 称重复核能不能替代扫码？

不能。本机读数：漏装占整包 1% 时检出率只有 **5.75%**，2% 时 **17.35%**。称重只能抓「缺一大件」，它是**扫码的补充**，不是替代。

### 11. 盘点差异要不要当天调平？

不要。差异要**先归因再调整**：`COUNT_ERROR` 当场调，`MISPLACED` 要移库（不动总量），`UNRECORDED` 要补流水（追作业人），`LOSS` 要审批。当天全部调平，等于把四类问题都变成「数错了」。

### 12. 仓库系统要不要自己做波次算法？

先做**规则**，再做**算法**：绝大多数仓用「按截单时间 + 温区 + 承运商」三条规则切波次就够了，路径用 S 形排序就能拿到大部分收益（本页读数：1,812 m → 333.6 m）。等规则稳定了再考虑最大间隙与 TSP 近似。

## 三、止血五步

线上出问题时的固定动作，顺序不能反：

1. **先冻住源头**：把出问题的库位置 `LOCKED`，或把波次置 `CANCELLED`。不要在问题扩散时继续拣货。
2. **再取证**：导出该库位最近 20 条 `stock_txn`、该波次全部 `pick_task`、相关包的 `package_item`。**先导数据再改数据**。
3. **再定位断点**：跑三条闭合查询（Q1 余量 = Σ流水、Q2 快照递推、Q6 交接三方），哪条不为 0，断点就在那一段。
4. **再最小修复**：只补那一笔差额，不重算历史。重算历史会把「已知的错」变成「未知的错」。
5. **最后补闸门**：把这次的原因变成一条判据（`CHECK`、唯一索引、条件更新），否则下周还会再来一次。

::: danger 止血时最常犯的三个错
1. **先改数据后取证。** 改完之后你连「改之前是什么样」都不知道，复盘只能靠回忆。
2. **用「重跑一遍」修复。** 重跑会再扣一次库存，且流水多一条——这就是「越修越乱」的来源。
3. **只修这一单，不做闸门。** 同一根因会在别的库位、别的波次再犯，而每次都要重新排查。
:::

## 四、术语表

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 波次 | wave | 把多个订单合并成一次拣货作业 |
| 短拣 | short pick | 到库位发现货不够，按实拣量记账 |
| 上架 | putaway | 把收货后的货放到指定库位 |
| 越库 | cross-dock | 到货后不上架，直接分拨出库 |
| FEFO | First Expired First Out | 先到期先出，有效期品类必用 |
| FIFO | First In First Out | 先进先出，按收货时间 |
| 循环盘点 | cycle count | 每天盘一部分库位，不停业 |
| 盲盘 | blind count | 盘点单不显示账面数 |
| 动碰盘点 | opportunistic count | 拣货时顺带清点手边库位 |
| 库位 | bin / location | 一个可存放的最小物理位置 |
| SSCC | Serial Shipping Container Code | GS1 的 18 位物流单元标识 |
| 体积重 | volumetric weight | 按体积折算的计费重量 |
