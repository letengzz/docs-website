# 常见问题与分诊

<p style="text-align:center;"><img src="../assets/rv-logo.png" style="zoom:75%;" /></p>

收入相关的工单有一个共同特征：**报上来的现象永远是「数不对」，而真正的原因在三个环节之外**。这一页把「数不对」拆成一张分诊表——先定位是哪一类，再按顺序查。

::: tip 一句话理解
**先问「差在哪一期」，再问「差多少」，最后才问「为什么」。** 顺序反了，就会一头扎进分摊算法，而问题其实在期间归属。
:::

本页判据族 `RVQ-A` ~ `RVQ-H`，共 8 条，定义在最后一节。

## 止血五步

数错了要先止血，再找根因。顺序不能换：

1. **冻结账期。** 先锁住当前期间，防止边查边变——否则你查到的数和财务看到的数不是同一份。
2. **拉三条线。** 同期导出「已确认 / 已开票 / 已收款」三列，按合同对齐。差异落在哪两列之间，就锁定在哪一段。
3. **定位到合同。** 不要从总额开始拆，直接从差得最多的 10 份合同看起；总额差异几乎总是少数合同贡献的。
4. **判断方向。** 「算早了」还是「算晚了」——前者要冲回，后者要补确认，两者的分录方向相反，处置流程也不同。
5. **写调整分录并留痕。** 调整必须带原因码与原始凭证号，进 `close_run`；下一期不许「悄悄改回来」。

::: danger 三个「止血」动作会造成二次伤害
1. **直接 UPDATE 已确认的明细金额。** 历史被覆盖，审计无法回答「原来是多少」。正确做法是**追加一条反向明细**（负数），保留原记录。
2. **把差异挂到「其他」科目。** 它会在下一个季度变成一笔谁也解释不清的余额。正确做法是挂到明确的待查科目，并在 30 天内清掉。
3. **关账后重跑月结覆盖数据。** 关账后的任何变更都要走调整分录，不能重跑主流程——重跑会同时改动已归档的披露数字。
:::

## 十二问

**Q1：合同签了但客户还没付款，能确认收入吗？**
能，只要五要件满足（含「对价很可能收回」的评估）。收入确认看履约，不看收款；收款只影响应收与现金。

**Q2：开票了但服务还没开始，收入怎么记？**
不确认收入，记合同负债。开票只是取得收款权，与履约无关。

**Q3：一次收三年钱，能不能一次确认？**
不能。要么按服务期分摊（时段法），要么先记合同负债再逐期释放。间隔超过 1 年还要考虑融资成分。

**Q4：赠品要不要分摊价格？**
看它是否构成单项履约义务。促销赠品若只是「履行主合同的必要成本」，不分摊；若客户可以单独选择、单独受益，则要按单独售价分摊。

**Q5：运费是收入还是成本？**
看谁是主要责任人。自营发货、运费是履约成本 → 计入销售费用或营业成本；代客户安排运输且不控制服务 → 可能构成单项履约义务。

**Q6：软件许可怎么确认？**
区分「使用权」（时点，交付即确认）与「访问权」（时段，按期间确认）。判断依据是客户能否在许可期内持续获得更新，以及不更新时能否继续使用。

**Q7：客户违约不付尾款了，收入要冲回吗？**
不冲收入，计提坏账。收入确认的是「履约」，客户不付款是信用风险，走减值。

**Q8：一份合同里有硬件、软件、三年服务，要拆几个义务？**
先做两个测试：能否单独受益、在合同内是否可明确区分。硬件与软件通常合并（重大整合），三年服务通常单列。

**Q9：验收一直不来，收入就一直不确认吗？**
看合同有没有「视为验收」条款。有就落成定时任务自动写 `accepted_at`；没有就要推动业务，不能靠财务手工填日期。

**Q10：汇率变了，历史收入要不要重算？**
不重算。确认时按当时汇率快照入账，汇兑差异走财务费用。

**Q11：跨年合同在年末怎么处理？**
按进度确认到 12 月 31 日，剩余部分形成合同负债或 RPO，在附注披露。

**Q12：审计问「为什么这个月确认这么多」，怎么答？**
答三件事：履约义务是哪几个、进度是怎么量的（分子分母各是什么）、证据在哪里（快照 ID、验收单号）。答不出第三条，前两条也不算数。

## 二十项自查清单

| # | 自查项 | 通过标准 |
| --- | --- | --- |
| 1 | 五个金额是否分列存储 | 无一个字段身兼两职 |
| 2 | `revenue_entry` 是否有三列唯一键 | 重复插入报错 |
| 3 | 五要件是否由视图算出 | 无 `is_ready` 冗余布尔 |
| 4 | 每个义务是否有 `timing` | 无空值 |
| 5 | 时段法是否有 `method` | 无空值 |
| 6 | 时点法是否有 `control_transfer_at` + `basis` | 无空值 |
| 7 | 交易价格是否带 `basis` | 无空值 |
| 8 | 分摊是否闭合 | `HAVING diff<>0` 为 0 行 |
| 9 | 比例之和是否为 1 | 误差 < 1e-6 |
| 10 | 余额是否带 `>= 0` 约束 | 负值写不进 |
| 11 | 是否保留合同负债发生额 | 能算出月度增减 |
| 12 | 可变对价是否有约束值 | 无空值 |
| 13 | 退货是否同时有负债与资产 | 两者均非零 |
| 14 | 变更分支是否受 CHECK 约束 | 矛盾组合写不进 |
| 15 | 退款是否幂等 | 重放不重复冲 |
| 16 | 期间是否存 `YYYY-MM` | 无时间戳边界比较 |
| 17 | 分解表是否先去重 | 合计 = 主表 |
| 18 | RPO 是否可逐合同复算 | 抽样差 = 0 |
| 19 | 月结是否留 `run_no` | 重跑有记录 |
| 20 | 会计政策是否落成开关 | 四组开关可查 |

## 判据清单

| 编号 | 判据 | 怎么验 |
| --- | --- | --- |
| `RVQ-A` | 十类现象的分诊表覆盖「期间 / 时点 / 分摊 / 变更 / 余额 / 披露」六个方向 | 六方向各至少一行 |
| `RVQ-B` | 每一行都能独立指向一页，不出现「见上文」 | 十行链接全部可达 |
| `RVQ-C` | 止血五步的顺序固定且不可合并 | 步骤编号存在，且第一步为冻结 |
| `RVQ-D` | 三个二次伤害动作有正确写法 | 每条 `danger` 都给出替代做法 |
| `RVQ-E` | 十二问每问都能用一句话回答，不出现「视情况」作为唯一答案 | 逐问检查 |
| `RVQ-F` | 自查清单二十项均可机械判定 | 每项都有可执行命令或唯一条件 |
| `RVQ-G` | 术语表与正文用词一致（同一概念不换词） | 抽查五个术语，正文用法统一 |

## 术语表

| 术语 | 英文 | 一句话定义 |
| --- | --- | --- |
| 履约义务 | performance obligation | 合同中承诺转移的、可明确区分的商品或服务 |
| 交易价格 | transaction price | 预期有权收取的对价，含可变部分并受约束 |
| 单独售价 | stand-alone selling price | 单独销售该商品时的价格，分摊的分母 |
| 合同资产 | contract asset | 收款权取决于时间之外因素的资产 |
| 合同负债 | contract liability | 已收对价而尚未履约的负债 |
| 剩余履约义务 | remaining performance obligation | 尚未履行部分对应的交易价格（RPO） |
| 重大融资成分 | significant financing component | 付款与履约时间差带来的融资效果 |
| 累计追补 | cumulative catch-up | 变更后按累计进度一次性调整的差额 |

## 验证方式

分诊表是否可用，不看它写得多整齐，看能不能**盲测**：

```shell
# 1) 盲测：把十类现象各造一条，只看现象能否在 3 分钟内定位到页
#    做法：从 revenue_entry 里挑一条异常记录，遮住原因，让同事按分诊表走一遍
sqlite3 /tmp/rv-lab/rv.db "SELECT period, count(*), sum(amount) FROM revenue_entry GROUP BY period ORDER BY period;"

# 2) 禁止项反测：三个二次伤害动作必须被文档明确禁止
grep -c "三个「止血」动作会造成二次伤害" docs/Backend/RevenueRecognition/FAQ/index.md   # 预期 1

# 3) 答案可查：十二问里每一问的答案都能在某一页找到对应小节
python3 utils/audit/linkexistcheck.py | grep RevenueRecognition/FAQ    # 预期无输出（死链为 0）
```
