# 收入确认与递延收入工程

<p style="text-align:center;"><img src="./assets/rv-logo.png" style="zoom:75%;" /></p>

「这个月收了多少？」——这个问题有五个正确答案。合同签了 100 万、客户打了 60 万、发票开了 60 万、货交了 8 成、账期还差 15 天。销售说 100 万，出纳说 60 万，财务说 33 万。三个人都没说谎，他们说的是**五个不同的数**，而其中只有一个能进利润表。

这个专题讲的是**怎么让系统在正确的那一天，把正确的金额，记到正确的期间**——不是「记账」，记账是[复式记账与分录](../Ledger/DoubleEntry/index.md)的事；这里讲的是**在记账之前，怎么判断「该不该记、记多少、记到哪一期」**。

::: tip 一句话理解
**收入不是「钱到了」，而是「义务没了」。** 客户把钱给你，你欠他一批货或一段服务——这笔欠就是负债；货交了、服务期过了，负债才转成收入。所以收入确认的本质是**一次负债的释放**，而不是一次现金的流入。
:::

## 三个必须先接受的前提

1. **收入是一条时间轴，不是一个状态。** 绝大多数工程事故不是「算错了」，而是「算早了」或「算晚了」——而这两种错在报表上都表现为「某个月特别好、下个月特别差」，看起来像业务波动。
2. **每一次确认都必须能回答「凭哪一条证据」。** 准则要的不是准确，是**可复核**。所以系统里必须留下「为什么这一期确认这么多」的凭据：进度快照、验收单号、交付时间戳、变更单号。
3. **多确认收入不会报错。** 少确认会被业务追着问，多确认所有人都高兴——所以这条链上的错**几乎全是安静的**，只能靠对账与断言抓出来。

## 版本组织说明

本专题**不建版本目录**（如 `RevenueRecognition2020/`）。三条理由：

1. **换代的是准则版本，不是判据。** IFRS 15（2014 年 5 月发布，2018 年 1 月 1 日起生效）、ASC 606 与中国《企业会计准则第 14 号——收入》（财会〔2017〕22 号）三者已经趋同，五步法与时段/时点判定在三种口径下**一字不差**；差异集中在披露格式与施行时间，属同一页里的两行注。
2. **多套口径长期并存于同一集团。** 境内母公司按 CAS 14、境外子公司按 IFRS 15、美股上市主体按 ASC 606，这不是三个时代，而是**同一份代码的三个开关**。
3. **真正需要按大版本组织的是「同一份代码两套写法」**，比如 [`Spring5`/`Spring6`](../Java/Frame/Spring/index.md)、[`Vue2`/`Vue3`](../../Frontend/Frame/Vue/index.md)。这里的差异可以在一张对照表里讲完。

库内按大版本建目录的先例见 [`Spring5`/`Spring6`](../Java/Frame/Spring/index.md) 与 [SpringBoot `v2`/`v3`](../Java/Frame/SpringBoot/index.md)。

## 事实与口径速览

| 事项 | 口径 | 出处 |
| --- | --- | --- |
| 国际准则 | **IFRS 15**《与客户之间的合同产生的收入》，2014 年 5 月发布，**2018-01-01** 起生效（2015 年 9 月决定推迟一年） | IASB |
| 美国准则 | **ASC 606**（ASU 2014-09），公众主体适用于 **2017-12-15** 之后开始的年度期间 | FASB |
| 中国准则 | 《企业会计准则第 14 号——收入》（财会〔2017〕22 号，2017-07-05）：境内外同时上市 **2018-01-01**、其他境内上市 **2020-01-01**、非上市 **2021-01-01**，允许提前执行 | 财政部 |
| 核心模型 | 五步法：识别合同 → 识别履约义务 → 确定交易价格 → 分摊 → 确认 | 三项准则一致 |
| 时段判定 | 三个条件满足任一即「时段」；否则「时点」 | IFRS 15.35 |
| 时点指标 | 五个指标：现时收款权、法定所有权、实物转移、主要风险报酬、客户已接受 | IFRS 15.38 |
| 融资成分 | 付款与履约间隔超过 **1 年**要考虑重大融资成分（有实务简化） | IFRS 15.60~65 |
| 剩余履约义务 | **RPO**：未履行（或部分未履行）的履约义务对应的交易价格 | ASC 606-10-50-13 |

## 验证方式

专题级的验收不看文章数量，看三件事能不能在本机复现：

```shell
# 1) 判据编号唯一、无撞号（预期 E=0）
python3 utils/audit/judgeidcheck.py | tail -1

# 2) 目录页的判据总览表与实际声明一致（预期 E=0）
python3 utils/audit/judgesumcheck.py | grep RevenueRecognition

# 3) 页面收尾三件套齐全：验证方式 + 参考资料（预期无输出）
python3 utils/audit/tailcheck.py --root . | grep RevenueRecognition
```

三条全过，说明这十一页在结构上「读得通、判得准、收得住」；内容是否正确，要靠[实战](./Practice/index.md)里那三个**必须失败**的反向用例来证明。
