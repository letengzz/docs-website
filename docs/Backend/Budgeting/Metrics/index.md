# 度量与验收：执行率的分母是什么

「预算执行率 65%」——这个数字在 7 月是正常还是异常？答案完全取决于分母：如果分母是年预算，7 月本该到 58%，65% 说明略超；如果分母是「已过期间的额度」，65% 说明还有 35% 的空间，而剩下只有 5 个月。

同一个分子、两种分母，得出两个相反的结论。**预算体系的绝大多数误判，都发生在分母上。**

::: tip 一句话理解
执行率只有一个定义：**已花 ÷ 可花**。麻烦在于「可花」有三个版本——全年授权、已过期间授权、调整后授权。**三个都要显示，只显示一个就是误导。**
:::

## 一、六个度量，四本账各有自己的准确率

![预算体系的六个度量](../assets/bp-metrics.svg)

| 环节 | 度量 | 分母 | 用来回答 |
| --- | --- | --- | --- |
| 编制 | 三轮内收敛率 | 参与编制的中心数 | 编制流程是否有效率 |
| 审批 | 阈值合规率 | 全部单据 | 有没有漏批/拆单 |
| 控制 | 阻塞率 / 告警转化率 | 全部申请 / 全部告警 | 控制是否在"该拦的才拦" |
| 记账 | 四本账差额 | 预算行数 | 有多少行的可用额度为负 |
| 差异 | 归因覆盖率 | 差异总金额 | 有多少差异能被解释 |
| 预测 | MAPE / bias | 已完成的预测期数 | 预测能不能用来改动作 |

把六个压成一个「预算执行率」，等于把六个不同的问题合并成一个不能回答任何问题的数字。

## 二、执行率的三个分母

本机读数（年预算 1,200 万、7 月、时间进度 58.33%）：

| 部门 | 已用 | 分母 = 年预算 | 分母 = 已过期间额度 | 结论差异 |
| --- | --- | --- | --- | --- |
| A | 5,800,000 | 48.33% | 82.86% | 「落后 10.0 点」vs「快用完了」 |
| B | 7,800,000 | 65.00% | **111.43%** | 「落后 6.7 点」vs「**已超 11.4%**」 |

B 部门是最典型的误判：按年预算口径，它 65% 的执行率比时间进度 58.33% 只高 6.7 个点，看起来「略有超前但可接受」；按已过期间口径，它**已经超了 11.4%**。

```sql
-- 三个分母并列，缺一不可
SELECT cc,
       SUM(amount_ytd)                                            AS used,
       SUM(amount_year)                                           AS budget_year,
       SUM(amount_year) * :elapsed_months / 12.0                  AS budget_to_date,
       ROUND(SUM(amount_ytd) * 100.0 / SUM(amount_year), 2)        AS pct_of_year,
       ROUND(SUM(amount_ytd) * 100.0
             / (SUM(amount_year) * :elapsed_months / 12.0), 2)     AS pct_of_ytd_budget
  FROM budget_ytd
 GROUP BY cc;
```

::: danger 只报「年预算分母」会掩盖什么
1. **前期花太快**：前 7 个月花了 65%，剩下 5 个月只有 35% 的额度，而业务节奏没有变慢——年底必超。
2. **季节性业务被误判**：Q4 占全年 40% 的业务，7 月只花 45% 是正常的，用年预算分母会显示「落后」，然后催促花钱。
3. **调整后预算被忽略**：年中追加了 200 万，年预算分母还是旧的 1,200 万，执行率被系统性低估。
:::

## 三、时间进度与支出进度必须并列

单独看支出进度没有意义，必须与时间进度放在一起：

| 情形 | 支出进度 − 时间进度 | 含义 | 动作 |
| --- | --- | --- | --- |
| ≈ 0（±3 点） | 同步 | 按计划走 | 无 |
| 负 3~10 点 | 落后 | 项目延期或需求不足 | 问原因，别催花钱 |
| 负 > 10 点 | 严重落后 | 预算可能高估 | 考虑调剂 |
| 正 > 10 点 | 严重超前 | 年底必超 | 立即干预 |

本机 A 部门 −10.0 点、B 部门 +6.7 点。**注意这两个数都是用年预算分母算的**，所以 B 的 +6.7 点看起来不严重——这就是第二节说的掩盖。

## 四、四本账各自的准确率

| 账 | 度量 | 计算 | 本机基线 |
| --- | --- | --- | --- |
| 预算 | 版本一致性 | 汇总行数 = 冻结版行数（非零行） | 应完全相等 |
| 承诺 | 在途准确率 | 已收货但 `received_at` 为空的承诺占比 | 应 < 1% |
| 实际 | 关账完整率 | 已关账期间缺失实际数的预算行占比 | 应 < 2% |
| 可用 | 负额度行数 | `available < 0` 的行数 | 应为 0 |

第三条最容易被忽略：某个科目这个月**根本没发生**，和「这个月的数据还没进来」，在表里长得一模一样（都是 0 或 NULL）。区分它们只能靠「关账标记」：

```sql
-- 已关账期间仍缺实际数的行（不是「没花钱」，是「没入账」）
SELECT b.cc, b.acct, b.period
  FROM budget_line b
  JOIN period_close p ON p.period = b.period AND p.closed_at IS NOT NULL
  LEFT JOIN actual a ON a.cc = b.cc AND a.acct = b.acct AND a.period = b.period
 WHERE b.ver = 'V2' AND a.amount IS NULL;
```

## 五、控制指标：阻塞率与告警转化率

控制做得好不好，不看「拦了多少」，看**拦得对不对**：

| 指标 | 定义 | 健康区间 | 异常信号 |
| --- | --- | --- | --- |
| 阻塞率 | 被拒申请 / 全部申请 | 5%~15% | < 2%（形同虚设）或 > 25%（口径错配） |
| 告警转化率 | 告警后调整额度的比例 | > 30% | < 10%（告警没人看） |
| 例外审批率 | 走例外的金额 / 总金额 | < 5% | > 15%（硬控被架空） |
| 阻塞后重提率 | 同日同科目再申请的比例 | < 20% | > 40%（在拆单） |

本机硬控阻塞 12.8%，落在健康区间；但这个数字本身不能说明「拦对了」——要把阻塞原因分成「口径错配」与「真实超支」两类，前者是配置问题，后者才是控制生效。

## 六、日报五行

一屏能说清的经营日报只需要五行：

| 行 | 内容 | 判据 |
| --- | --- | --- |
| 1 | 全年授权 / 已用 / 可用 | 三个数能相加对得上 |
| 2 | 本月 vs 预算、vs 时间进度 | 两个差都以「点」为单位 |
| 3 | 前三大差异（金额） | 每个都带归因标签 |
| 4 | 承诺在途金额与占比 | 占比 > 20% 标黄 |
| 5 | 全年预测 vs 预算（缺口） | 缺口为正即需动作 |

超过五行的日报没人看，少于五行的日报回答不了「现在该怎么办」。

## 判据

本页判据族 `BPM-A` ~ `BPM-H`，共 8 条，逐条可判定：

| 编号 | 判据 | 怎么判 |
| --- | --- | --- |
| `BPM-A` | 执行率三个分母同时呈现（年/已过期间/调整后） | 报表含三列 |
| `BPM-B` | 时间进度与支出进度并列，差值以「点」呈现 | 报表含 `gap_pts` 列 |
| `BPM-C` | 四本账各有独立准确率指标 | 四个指标在指标字典里 |
| `BPM-D` | 编制质量指标（收敛轮次、逾期提交、返工次数） | 三个字段可查 |
| `BPM-E` | 控制指标含阻塞率与告警转化率，阻塞有原因分类 | 分类维度 ≥ 2 |
| `BPM-F` | 差异归因覆盖率按金额算，不按条数算 | 指标定义写「金额」 |
| `BPM-G` | 预测指标含 MAPE 与 bias，至少有 3 期 | 指标表有 3 期以上 |
| `BPM-H` | 日报五行固定，每行有判据与阈值 | 报表模板与阈值表同版本 |

## 验证方式

先验证同一个分子在两个分母下的结论差异，再验证「时间进度与支出进度」的读法：

```shell
# 1) 本页判据 8 条
grep -o 'BPM-[A-H]' docs/Backend/Budgeting/Metrics/index.md | sort -u | wc -l

# 2) 三个分母
python3 - <<'PY'
annual, used, elapsed = 12_000_000, 7_800_000, 7
print("年预算分母 %.2f%%" % (used / annual * 100))
print("已过期间分母 %.2f%%" % (used / (annual * elapsed / 12) * 100))
print("时间进度 %.2f%%" % (elapsed / 12 * 100))
PY

# 3) 全库判据不撞号
python3 utils/audit/judgeidcheck.py --root . | tail -1
```

预期输出：第一条 `8`；第二条依次打印 `年预算分母 65.00%`、`已过期间分母 111.43%`、`时间进度 58.33%`；第三条 `E=0`。若第二条两个分母下的数字相同，说明你的 `elapsed` 被当成了 12。
