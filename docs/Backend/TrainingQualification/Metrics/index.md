# 度量与合规报表：四个分母

资质报表最容易骗人的地方不是数据错，而是**分母换了一个**：在册 3,000 人还是应培 2,035 人，覆盖率都能算出来，都能叫「覆盖率」，差的 12.17% 足够让一个指标从达标变成不达标。

![度量：四个分母，一个也换不得](../assets/tq-metrics.svg)

## 一、三个分母：83.33% / 83.31% / 83.05%

本机读数（基准日 2026-11-03）：

| 分母 | 分母人数 | 分子（参加过培训的人） | 覆盖率 |
| --- | --- | --- | --- |
| 在册全员 | 3,000 | 2,500 | **83.33%** |
| 在岗全员（`ACTIVE`） | 2,648 | 2,206 | **83.31%** |
| 应培（在岗且有强制要求） | 2,035 | 1,690 | **83.05%** |

三个数看着差不多，但**分母之间差 965 人**（3,000 vs 2,035）。真正需要警惕的是另一件事：「应培」比「在册口径的应培」少 **282 人（12.17%）**——那 282 人是休假/借调/待离职但仍在册的人。

::: danger 「覆盖率」这个词的四种偷换
1. **分母偷换**：报告写 83.33%（在册），实际应培口径是 83.05%——数字更好看，但责任范围变小了。
2. **分子偷换**：把「报过名」算成「培训过」（报名 5,950、到场 5,117，差 14%）。
3. **时间偷换**：把「历史累计培训过」算成「本年度已培训」。
4. **对象偷换**：把「参加过一次任意培训」算成「完成该岗位要求的全部培训」。
:::

## 二、四个必须一起看的指标

| 指标 | 定义 | 本机值 | 单独看会怎么骗人 |
| --- | --- | --- | --- |
| 覆盖率 | 有证据的人 / 应培的人 | 83.05% | 把没证的人调走也能到 100% |
| 及时率 | 到期前完成续证的比例 / 全部到期数 | 需按窗口算 | 提前期只有 3 天时也能 95% |
| 到期风险 | 未来 30 / 60 / 90 天到期数 | 274 / — / — | 为 0 可能是「根本没录外部证书」 |
| 准入拦截率 | 拦截人次 / 打卡人次 | 719 人缺证 | 拦截率高可能是「判定点太靠后」 |

四个数必须**成组出**，且每个都带分母。单独一个数一定可以被优化到好看。

## 三、及时率：分子分母都要带窗口

```sql
-- 及时率：在某窗口内到期、且在到期前完成续证的比例
SELECT
  count(*) AS due_cnt,
  sum(CASE WHEN renewed_at IS NOT NULL AND renewed_at < expire_date THEN 1 ELSE 0 END) AS on_time
FROM (
  SELECT c.cert_id, c.expire_date,
         (SELECT min(c2.issue_date) FROM cert c2
           WHERE c2.emp_no = c.emp_no AND c2.qual_id = c.qual_id
             AND c2.issue_date > c.issue_date) AS renewed_at
  FROM cert c
  WHERE c.cert_status IN ('VALID','EXPIRED')
    AND c.expire_date >= :win_start AND c.expire_date < :win_end
) t;
-- 期望：on_time / due_cnt，且 due_cnt > 0（为 0 时拒绝判定）
```

两个坑：

1. **`renewed_at` 用 `min(issue_date)` 取「下一张证」**：如果这个人在同一资质上有多次重发，`min` 取到的是最早的重发，而不是紧接的那张。正确做法是按 `issue_date` 排序取「紧随其后的第一条」。
2. **分母为 0 时直接返回 0%**：某个月没人到期，及时率会显示 0%，看起来像事故。分母为 0 时应返回 `NULL` 并标注「无样本」。

## 四、到期风险：三个窗口一起看

| 窗口 | 用途 | 本机（30 天） |
| --- | --- | --- |
| 30 天 | 本周排班要避开的人 | 274 张 / 日均 9.1 |
| 60 天 | 下月复训班次容量 | — |
| 90 天 | 外部培训机构的报名截止 | — |

三窗口一起看才能发现「波峰」：如果 30 天 274 张、60 天 300 张、90 天 900 张，说明第 3 个月有一个到期高峰，现在就要加开班次。

## 五、审计抽样：抽 35 条能覆盖多少风险

合规审计通常给一个抽样量（例如 35 条）。抽谁决定了能不能发现问题：

| 抽样方式 | 样本 | 命中问题数 | 命中金额/风险占比 |
| --- | --- | --- | --- |
| 随机抽 35 条 | 35 | 4 | 11.4% |
| 按「即将到期 + 外部录入」分层抽 35 条 | 35 | 13 | 37.1% |
| 全量校验 | 6,598 | 919 | 100% |

结论：**抽样必须分层**。分层维度就三个——来源（内部/外部）、剩余有效期（<30 天）、是否曾被吊销。这三层覆盖了本机 919 张「状态 VALID 但已过期」中的绝大多数。

## 六、日报：五行就够

| 行 | 内容 | 判读方式 |
| --- | --- | --- |
| 1 | 应培人数 / 有证据人数 / 覆盖率（带分母） | 与上周比，而不是与 100% 比 |
| 2 | 30 / 60 / 90 天到期数 | 环比突增即预警 |
| 3 | 昨日拦截人次（分判定点） | 集中在某一判定点说明该点配置有问题 |
| 4 | 未闭环拦截（超期未处理） | 这一行最容易长期不为 0 |
| 5 | 昨日新增/吊销/补录证书数 | 补录数突增说明签到设备或流程有问题 |

第 4 行值得单独强调：本机 719 名在岗缺证者，如果拦截都生成了待办但没人闭环，「未闭环」会稳定在 700 上下——**一个长期不动的数字等于没有这个指标**。

## 七、判据清单

本页判据族 `TQX-A` ~ `TQX-H`，共 8 条。

| 编号 | 判据 | 判定方式 |
| --- | --- | --- |
| `TQX-A` | 覆盖率带分母与口径 | 报表返回 `numerator` / `denominator` / `basis` |
| `TQX-B` | 分子不等于报名数 | 分子来自 `attendance` 或 `cert`，不来自 `enrollment` |
| `TQX-C` | 及时率带窗口 | SQL 含 `expire_date >= :win_start` |
| `TQX-D` | 分母为 0 返回空 | 返回 `NULL` 而非 0 |
| `TQX-E` | 到期风险三窗口 | 报表同时给出 30 / 60 / 90 天 |
| `TQX-F` | 抽样可分层 | 抽样脚本支持按来源/剩余期分层 |
| `TQX-G` | 拦截分判定点统计 | 报表按 `gate_point` 分组 |
| `TQX-H` | 未闭环单列 | 存在「超期未处理」计数 |

## 八、验证方式

```shell
# 1) 三个分母的覆盖率（本机读数）
python3 -c "
for den, num in ((3000,2500),(2648,2206),(2035,1690)):
    print(den, num, round(num/den*100,2))"
# 期望：
# 3000 2500 83.33
# 2648 2206 83.31
# 2035 1690 83.05

# 2) 应培口径与在册口径的差
python3 -c "print(2317-2035, round((2317-2035)/2317*100,2))"
# 期望：282 12.17

# 3) 分母为 0 时应返回 None 而不是 0
python3 -c "
def rate(n, d): return None if d == 0 else round(n/d*100,2)
print(rate(0,0), rate(1,2))"
# 期望：None 50.0

# 4) 分层抽样与随机抽样的命中差异（本机读数）
python3 -c "print('random 4/35 =', round(4/35*100,1), '%'); print('stratified 13/35 =', round(13/35*100,1), '%')"
# 期望：random 4/35 = 11.4 % / stratified 13/35 = 37.1 %
```
