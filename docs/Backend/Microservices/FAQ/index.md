# 微服务常见问题与最佳实践

本页汇总微服务落地过程中最高频的问题与坑：服务发现失败、配置不生效、网关 503、雪崩、事务回滚不彻底、链路断连等，并给出可直接照抄的排查路径与最佳实践清单。

## 服务之间调用失败，怎么排查

按以下顺序逐层检查：

```text
注册中心（实例健康？）→ 服务名（拼写一致？）→ 网络（端口/防火墙？）→ 负载均衡（选到死实例？）→ 业务异常
```

1. Nacos 控制台确认目标服务实例在线且健康。
2. 确认消费者用的服务名与提供者注册名完全一致（大小写、连字符）。
3. 在提供者机器上 `curl http://localhost:端口/actuator/health` 确认接口本身可用。
4. 检查消费者日志中的负载均衡是否选到已下线实例（本地缓存未刷新）。
5. 用链路追踪看调用是否到达网关、是否被鉴权/限流拦截。

## 配置改了不生效

| 原因 | 解法 |
| --- | --- |
| Bean 没加 `@RefreshScope` | 给需要刷新的 Bean 加注解 |
| 本地配置优先级更高 | 检查是否被本地 `application.yml` 覆盖 |
| Data ID 命名不匹配 | 确认 `服务名-环境.yaml` 规则 |
| `spring.config.import` 没配 | 加上 `optional:nacos:xxx.yaml` |
| 配置类型不匹配 | 确认文件扩展名 yaml/properties 与配置一致 |

详见 [配置中心](../ConfigCenter/index.md)。

## 网关 503 / 无法路由

1. **服务没注册**：Nacos 服务列表里没有该服务 → 检查服务启动是否成功、依赖是否齐全。
2. **URI 用了 IP**：应使用 `lb://服务名` 而非写死地址。
3. **谓词不匹配**：请求路径与 `Path` 规则对不上，或 `StripPrefix` 层级数错误。
4. **下游全挂**：实例都不可用，网关无目标可转 → 检查服务健康与熔断状态。
5. **端口冲突**：网关端口被占用，启动失败。

## 出现雪崩征兆，先做什么

```text
症状：某个接口 RT 暴涨 → 线程池满 → 相关接口全部超时
```

1. **先止损**：在网关/入口把异常服务的流量摘掉（权重归零或开启熔断）。
2. **隔离**：确认熔断器、隔离舱（Bulkhead）、超时配置是否生效。
3. **降级**：临时返回缓存/兜底数据，保证核心链路可用。
4. **定位**：用链路追踪找出变慢的依赖（SQL？第三方？锁？）。
5. **恢复**：修好下游后按“半开→关闭”自动恢复，人工确认再放量。

## 分布式事务回滚不彻底

排查清单：

| 检查项 | 说明 |
| --- | --- |
| `undo_log` 表存在 | Seata AT 模式每个库都必须建 |
| `@GlobalTransactional` 在入口 | 必须标在事务发起方 |
| 参与者方法有 `@Transactional` | 本地事务由 Seata 代理接管 |
| 远程调用在事务内 | 确认 Feign 调用被 Seata 拦截（`seata-spring-boot-starter`） |
| 数据库账号有权限 | undo_log 需要 DML 权限 |
| 补偿幂等 | TCC/SAGA 的补偿方法必须幂等 |

## 链路追踪看不到完整链路

1. 确认所有相关服务都接入同一套追踪系统。
2. 异步线程池中上下文丢失 → 用包装线程池透传 traceId。
3. 采样率太低 → 错误/慢请求全采，正常请求抽样。
4. 跨 MQ/第三方调用没透传 traceId → 在消息 Header 里带 traceId。

## 服务拆到什么时候算过度

出现以下信号说明拆太细：

- 一次需求变更要发布 5 个以上服务；
- 服务间大量同步调用，链路图像蜘蛛网；
- 团队无法完整理解系统，上线全靠“联调”；
- 基础设施成本远超业务价值。

对策：反向合并（Cohesion-based merging），把高耦合服务合并回一个；或引入模块化单体过渡。

## 微服务如何做测试

| 层级 | 工具 | 范围 |
| --- | --- | --- |
| 单元测试 | JUnit + Mockito | 单个类逻辑 |
| 契约测试 | Spring Cloud Contract | 服务间接口契约 |
| 组件测试 | Testcontainers | 单服务 + 真实中间件 |
| 集成测试 | Docker Compose 全栈 | 端到端主流程 |
| 压测 | JMeter / Gatling | 吞吐与容量 |
| 故障演练 | Chaos Monkey / 手动演练 | 熔断、回滚、降级 |

## 最佳实践清单

::: tip 微服务十诫
1. 按业务能力（限界上下文）拆分，宁粗勿细。
2. 每个服务独立数据库，禁止跨库直连。
3. 服务间只走 API/事件，禁止共享实体类与表。
4. 所有远程调用标配：超时 + 熔断 + 降级 + 重试预算。
5. 配置进配置中心，密钥加密，支持动态刷新与回滚。
6. 统一入口网关：路由、鉴权、限流、灰度。
7. 全链路追踪 + 结构化日志 + 指标监控三位一体。
8. 分布式事务能不上就不上，优先最终一致 + 对账。
9. 消费端必须幂等，消息至少一次投递。
10. 上线前必须做故障演练与回滚演练。
:::

## 验证方式

1. 用实战章节的骨架完整跑通“下单成功”与“库存不足回滚”两条路径。
2. 人为停掉一个服务，观察网关 503 兜底、熔断打开、自动恢复全过程。
3. 压测并记录：QPS、RT、错误率、线程池水位、数据库锁等待。
4. 每月一次故障演练，把演练报告归档。
