# 设计模式常见问题与最佳实践

本页汇总设计模式学习与落地中最常遇到的问题：什么时候用模式、什么时候别用、模式记不住、面试怎么答、以及反模式清单。

## 学了记不住，怎么办

1. **按问题记，不按名字记**：记“多个算法切换 → 策略”“对象创建复杂 → 工厂/建造者”。
2. **对照框架源码记**：Spring 里看代理/工厂/观察者，比死记强十倍。
3. **写一遍最小示例**：每个模式写 20 行 Demo，理解结构。
4. **用坏味道反推**：看到 if/else 爆炸想策略，看到 switch 创建想工厂。

## 什么时候用设计模式

出现以下**真实信号**再用：

| 信号 | 对应模式 |
| --- | --- |
| 同一算法的多版本切换 | 策略 |
| 新增类型要改 switch/if | 工厂、策略 |
| 对象参数多且可选 | 建造者 |
| 给已有对象加横切能力 | 代理、装饰器 |
| 通知/联动逻辑膨胀 | 观察者 |
| 处理链（鉴权→限流→转发） | 责任链 |
| 状态×动作判断矩阵 | 状态 |
| 复杂子系统对外统一入口 | 外观 |

## 什么时候别用

::: danger 模式反模式
1. **一个 if 就上策略**：分支稳定且少，直接 if 更清晰。
2. **单例滥用**：全局可变状态害死人，优先依赖注入。
3. **工厂套工厂**：抽象层级过度，代码没人能看懂。
4. **观察者链式爆炸**：事件满天飞，逻辑流无法追踪；控制事件范围。
5. **为“可能的未来”预埋抽象**：YAGNI，需求到了再抽象。
6. **模式命名当简历**：代码里全是模式注释，但没人维护得了。
:::

## 面试怎么答设计模式

回答模板：

```text
1. 一句话定义（解决什么问题）
2. 核心结构（2~3 个角色）
3. 代码/框架例子（Spring 哪里用了）
4. 优缺点与适用场景
```

高频考点：

- 单例的线程安全写法。
- 策略与状态的区别（策略：算法切换；状态：对象自身状态变化）。
- 代理与装饰器的区别（代理控制访问，装饰器叠加职责）。
- 模板方法在框架中的例子（JdbcTemplate/AQS）。
- Spring 中用到哪些模式。

## 模式怎么选：快速决策表

| 需求 | 模式 |
| --- | --- |
| 全局唯一 | 单例 |
| 由谁创建说不清 | 工厂方法 |
| 一族对象 | 抽象工厂 |
| 复杂参数对象 | 建造者 |
| 接口不兼容 | 适配器 |
| 动态加职责 | 装饰器 |
| 控制访问 | 代理 |
| 算法可切换 | 策略 |
| 固定骨架可变步骤 | 模板方法 |
| 一对多通知 | 观察者 |
| 请求逐级处理 | 责任链 |
| 状态行为变化 | 状态 |

## 最佳实践清单

::: tip 设计模式十诫
1. 先满足需求，再谈模式；YAGNI 优先。
2. 模式为“变化点”服务：识别哪里会变，再选模式。
3. 优先组合与接口，少用继承。
4. 单一职责是底线：上帝类先拆分。
5. 开闭原则用策略/工厂实现，别靠改 if。
6. 依赖倒置：业务依赖接口，细节靠注入。
7. 代理/装饰器注意性能与调试成本。
8. 观察者控制生命周期，防止内存泄漏。
9. 状态机先画图，再编码。
10. 每个模式写清楚“解决什么问题”，团队共享。
:::

## 验证方式

1. 对自己项目的代码做一次“坏味道扫描”，列出 5 个可应用模式的点。
2. 选一个点用模式重构，验证行为不变、测试通过。
3. 画一张“我的项目模式地图”：哪些类用了哪些模式，写进文档。
