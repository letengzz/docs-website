# 评标、专家与评分：去不去极值，冠军会换人

五个专家给五家投标人打分。汇总结果出来，A 第一，B 第二，差 0.6 分。

换个汇总方法——去掉一个最高分、一个最低分再平均——**B 变成第一**。

::: tip 一句话理解
评标不是「把分加起来」，是**用一套事先公布的口径把人的判断折算成一个可比的数**。口径必须在开标前固定，因为它在 4.33% 的项目里直接决定谁中标。
:::

本页判据族 `BTE-A` ~ `BTE-H`，共 8 条。

## 一、专家从哪来：随机抽取与回避

法规对评标委员会有两条硬约束：

| 约束 | 内容 | 依据 |
| --- | --- | --- |
| 人数与构成 | 五人以上单数，技术、经济专家不少于成员总数的 **2/3** | 招标投标法第三十七条 |
| 抽取方式 | 从专家库相关专业名单中**随机抽取**，任何单位个人不得指定 | 条例第四十六条 |
| 回避 | 与投标人有利害关系的应当主动回避 | 条例第四十六条 |

「随机」+「回避」这两件事放在一起，会出现一个反直觉的读数。

本机模拟：500 名专家，其中 75 名（15%）与某投标人有关联（同一单位、近亲属、项目前期参与过）。

| 抽取方式 | 抽到至少 1 名关联专家的概率 |
| --- | --- |
| 纯随机抽 5 人 | **55.79%** |
| 随机 + 回避过滤 | 0%（关联者不进入候选池） |

**超过一半的评审组，如果只做随机不做回避，会带上至少一个该回避的人。** 而这件事在系统里毫无痕迹——因为「抽了 5 个人」这个动作本身是合规的。

::: danger 回避不能靠专家自己申报
1. **只靠承诺书**：专家签「本人无利害关系」，签了就不管了。而「有没有关系」这件事，专家自己最清楚，也最有动机不说。
2. **只比对单位名称**：同一个集团的不同法人、母公司 vs 子公司，名称不同但实为关联。
3. **不记录回避判断的过程**：谁判的、依据什么、判了几个人——这些不留痕，等于没做。
:::

可用的做法是**三重比对 + 留痕**：单位（含股权关联）、人员（法定代表人、项目负责人、近亲属申报）、历史（近三年是否参与过该投标人项目）。

## 二、打分：客观分与主观分必须分开走

| 类型 | 例子 | 谁来定 | 能不能机器算 |
| --- | --- | --- | --- |
| 客观分 | 证书数量、业绩个数、注册资金、体系认证 | 规则 | 能 |
| 主观分 | 方案完整性、可行性、创新性 | 评委 | 不能 |
| 半客观分 | 工期承诺、付款条件响应 | 规则 + 判断 | 部分能 |

客观分交给评委手工填，是本页最贵的一个设计错误。本机 2,606 条客观分记录里，**238 条（9.13%）与证书数量对不上**——平均每 11 份标书就有 1 份打错。

错误不是随机的，它集中在两类情况：

| 情况 | 错法 | 原因 |
| --- | --- | --- |
| 证书数量多（≥5 个） | 少数 1 个 | 翻页时漏看 |
| 证书有重叠（同一证书多个副本） | 多数 1 个 | 把副本当独立证书 |

两类都可以用「按规则算 + 评委确认」消除：系统按证书清单算出应得分，评委只需确认「清单完整」，而不是从零数一遍。

## 三、汇总口径：三种算法，三个冠军

同一组专家分，至少有四种汇总方式：

| 口径 | 算法 | 特点 |
| --- | --- | --- |
| 算术平均 | Σ / n | 简单，但一个畸高分就能改写结果 |
| 去极值平均 | (Σ − max − min) / (n − 2) | 抗操纵，但样本少时不稳定（5 人只剩 3 人） |
| 中位数 | 排序取中 | 最抗异常，但丢失信息 |
| 加权平均 | Σ(wᵢ × sᵢ) / Σwᵢ | 用于「组长权重更高」的场景 |

本机 300 个项目、每项目 5~12 家投标人、5/7/9 名专家：

| 指标 | 值 |
| --- | --- |
| 算术平均 vs 去极值：**第一名变化** | **13 / 300（4.33%）** |
| 相邻名次分差 < 0.10 分 | 117 / 2,306（**5.07%**） |
| 专家个人分偏离项目均值 > 1.5σ | 70 / 2,090（3.35%） |

第一行是结论性的：**在 4.33% 的项目里，换一种加法就换一个中标人。** 这个比例不算高，但每一个都对应一次真实的质疑。

第二行解释了为什么：**5.07% 的相邻名次分差小于 0.1 分**。在这些位置上，「保留几位小数」「先四舍五入再排名还是排名后再舍入」都会改变结果。

::: warning 并列不是罕见事件
10 家投标人、分差 5 分左右的分布下，相邻两名差 0.1 分以内的概率是 5%。一个县一年 200 个项目，就有 10 个项目会遇到「要不要认定并列」。

招标文件里必须提前写死：**总分相同的，按投标报价低者优先；报价也相同的，按技术分高者优先。** 没写就等于把决定权留给了现场。
:::

## 四、价格分：一条反比曲线

低价优先法是最常见的算法：

```text
价格分 = 评标基准价 / 投标价 × 价格权重
评标基准价 = 满足招标文件要求且投标价格最低的投标报价
```

基准价 800 万元、权重 30 分时：

| 投标价 | 与基准价关系 | 价格分 |
| --- | --- | --- |
| 800 万 | 基准 | 30.00 |
| 880 万 | +10% | 27.27 |
| 1,000 万 | +25% | 24.00 |
| 1,200 万 | +50% | 20.00 |

三个必须自己算一遍的地方：

1. **它是一条曲线，不是直线**：+10% 扣 2.73 分，+25% 扣 6 分，+50% 扣 10 分。前半段每 1% 扣 0.27 分，后半段每 1% 只扣 0.2 分——**报高价反而「每块钱扣得少」**。
2. **基准价由谁决定**：如果基准价是「最低价」，那么最低价那家自动拿满分，其余按比例扣。这意味着**报价策略会向「压到最低」收敛**。
3. **四舍五入的位置**：先算分再舍入（27.2727 → 27.27）与先舍入再算（几乎不会有人这么写）结果不同；更隐蔽的是「总分保留 2 位」与「各项保留 2 位再求和」的差别——它只在部分数据上差 0.01，而 0.01 足够改变名次。

```python
# 两种写法，结果不同：先舍入后求和 vs 先求和后舍入
items = [(85.555, 0.45), (72.445, 0.25), (93.335, 0.10)]
a = round(sum(round(s, 2) * w for s, w in items), 2)   # 先舍入到 2 位再加权
b = round(sum(s * w for s, w in items), 2)             # 先加权再舍入
print(a, b)     # 65.95 65.94 —— 差 0.01，足以改变名次
```

## 五、澄清：可以问，但不能改

评标过程中，委员会可以要求投标人对**含义不明确的内容**作澄清，但有两条红线：

| 允许 | 禁止 |
| --- | --- |
| 澄清含义不清的文字 | 改变投标报价 |
| 补正明显的计算错误 | 改变实质性内容 |
| 说明技术方案的实现方式 | 补充招标文件未要求的内容 |

「明显的计算错误」这条最容易被滥用。可判定的口径是：**单价 × 数量 ≠ 总价**时，以单价为准修正总价；但**总价与单价都自洽、只是与别家差很多**时，不能以「算错了」为由要求改价。

```sql
-- 可自动识别的「明显计算错误」：单价×数量与总价不符
SELECT bid_id, item_id, qty, unit_price, line_total,
       ROUND(qty * unit_price, 2) AS recomputed
FROM bid_line
WHERE ABS(line_total - ROUND(qty * unit_price, 2)) > 0.01;
```

只有这类差异才允许澄清补正。其余的「价格不合理」属于评审判断，不是澄清事项。

## 六、评分表的最小字段集

```sql
CREATE TABLE score (
  score_id    TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES purchase_project,
  bid_id      TEXT NOT NULL REFERENCES bid,
  expert_id   TEXT NOT NULL REFERENCES expert,
  item_code   TEXT NOT NULL,          -- 评分项编号，对应 tender_doc.score_rule
  obj_score   REAL NOT NULL,          -- 客观分（可由规则复算）
  subj_score  REAL NOT NULL,          -- 主观分
  reason      TEXT,                   -- 主观分的理由（必填）
  scored_at   TEXT NOT NULL,
  UNIQUE (bid_id, expert_id, item_code)
);
```

四个设计点：

1. **主键到「项」**：只到「专家 × 投标人」这一层，就无法回答「技术分 45 分是怎么构成的」。
2. **客观分与主观分两列**：合成一列后，复核时无法区分「算错」与「判错」。
3. **主观分必须填理由**：不填理由的主观分，在投诉时无法自证。
4. **`item_code` 引用评分办法**：评分办法改版后，历史评分仍能对应到当时的项。

### 汇总写成视图，不写成代码

```sql
CREATE VIEW v_score_summary AS
SELECT s.project_id, s.bid_id,
       SUM(s.obj_score + s.subj_score)                       AS total_raw,
       AVG(s.obj_score + s.subj_score)                       AS total_avg,
       (SUM(s.obj_score + s.subj_score)
        - MAX(s.obj_score + s.subj_score)
        - MIN(s.obj_score + s.subj_score))
       / (COUNT(*) - 2)                                      AS total_trimmed,
       COUNT(*)                                              AS expert_cnt
FROM score s
GROUP BY s.project_id, s.bid_id;
```

视图的价值在于**两种口径可以同时算出、同时展示**。当有人质疑「为什么不是 B 中标」时，你可以当场把 `total_avg` 与 `total_trimmed` 两列并排给他看，并指出「招标文件第 42 页写的是哪一种」。

## 七、本页判据

| 判据 | 断言 | 验证方式 |
| --- | --- | --- |
| `BTE-A` | 专家人数 ≥5 且为单数 | 违规项目数为 0 |
| `BTE-B` | 技术经济专家 ≥2/3 | 比例 <2/3 的项目数为 0 |
| `BTE-C` | 关联专家不入库 | `conflict = 1` 的记录数为 0（触发器强制） |
| `BTE-D` | 客观分可由规则复算 | 复算值与记录值不一致的比例 <1% |
| `BTE-E` | 主观分必须有理由 | `subj_score > 0` 且 `reason` 为空的记录数为 0 |
| `BTE-F` | 汇总口径写进招标文件 | `score_rule` 里能读到 `aggregate` 键 |
| `BTE-G` | 并列规则事先约定 | 招标文件含「总分相同」的处理条款 |
| `BTE-H` | 评分项与办法版本对应 | 每条 `score` 的 `item_code` 都能在该版本找到 |

## 验证方式

```shell
# 1. 专家构成（期望 0 行）
sqlite3 bt.db "select project_id, count(*) c from expert_assign
               group by project_id having c < 5 or c % 2 = 0;"

# 2. 技术经济专家比例（期望 0 行）
sqlite3 bt.db "select a.project_id, sum(case when e.major='技术经济' then 1 else 0 end)*3.0/count(*)
               from expert_assign a join expert e on e.expert_id=a.expert_id
               group by a.project_id having 1.0*sum(case when e.major='技术经济' then 1 else 0 end)/count(*) < 2.0/3;"

# 3. 两种汇总口径的第一名是否不同（期望能出数，用于自查口径敏感性）
sqlite3 bt.db "select project_id,
                 (select bid_id from v_score_summary x where x.project_id=v.project_id order by total_avg desc limit 1) as win_avg,
                 (select bid_id from v_score_summary x where x.project_id=v.project_id order by total_trimmed desc limit 1) as win_trim
               from v_score_summary v group by project_id
               having win_avg <> win_trim;"
# 本机 300 个项目里 13 行（4.33%）——这一串就是「口径决定冠军」的清单
```

第 3 步不只是验证，它是一个可以日常跑的对账：**每次评标前先看一眼这个清单，就知道自己的汇总口径在历史上改变过多少次结果。**

## 参考资料

- 《中华人民共和国招标投标法》第三十七条：评标委员会由招标人的代表和有关技术、经济等方面的专家组成，成员人数为五人以上单数，其中技术、经济等方面的专家不得少于成员总数的三分之二。
- 《中华人民共和国招标投标法实施条例》第四十六条：评标委员会的专家成员应当从评标专家库内相关专业的专家名单中以随机抽取方式确定；与投标人有利害关系的应当主动回避。
- 《中华人民共和国招标投标法》第三十九条：评标委员会可以要求投标人对投标文件中含义不明确的内容作必要的澄清、说明或补正，但不得超出投标文件的范围或者改变投标文件的实质性内容。
- 《评标委员会和评标方法暂行规定》（七部委令第 12 号）第二十九条至第三十二条：经评审的最低投标价法与综合评估法的适用条件与计算要求。
