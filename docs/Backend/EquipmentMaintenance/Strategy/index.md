# 维护策略与间隔：BM / PM / CBM / PdM

<p style="text-align:center;"><img src="../assets/em-logo.png" alt="设备维护与可靠性工程" style="zoom:75%;" /></p>

大部分工厂的维护策略只有一句：「每月保养一次」。这句话之所以流行，不是因为它对，而是因为它**无法被证伪**——设备坏了，可以说「保养不到位」；设备没坏，也可以说「保养有效」。要让它变成可证伪的，必须回答两个问题：**这台设备该用哪种策略、间隔凭什么定这个数**。

本页判据族 `EQS-A` ~ `EQS-H`，共 8 条，定义在第七节。

## 一、四种策略，四种前提

![四种维护策略与失效分布](../assets/em-strategy.svg)

| 策略 | 触发条件 | 前提 | 典型对象 | 失效方式 |
| --- | --- | --- | --- | --- |
| BM 事后维修 | 坏了才修 | 失效后果可承受，且有替代 | C 类辅机、非关键备件 | 安静（成本后置） |
| PM 定期维护 | 到了时间 / 产量就做 | 失效与使用量强相关（β > 1.5） | 磨损件、油品、皮带 | 安静（做多了浪费，做少了照样坏） |
| CBM 状态维护 | 测点越过阈值 | 存在**可测的早期征兆** | 轴承振动、油液金属、温度 | 安静（阈值定错就白测） |
| PdM 预测维护 | 剩余寿命预测到点 | 有足够失效样本可建模 | A 类关键机组 | 安静（样本不够时是玄学） |

这四种不是「先进程度」的排序。**C 类设备做 PdM 是浪费，A 类设备只做 BM 是赌博。** 选择依据是三个变量：失效后果、征兆可测性、样本可得性。

## 二、决策路径：三问定策略

```text
第一问：失效会造成安全 / 环境 / 断线后果吗？
  ├─ 否 → BM（坏了再修），只要求备件可得
  └─ 是 → 第二问：失效前有可测量的早期征兆吗？
            ├─ 没有 → PM（按时间或产量），前提是 β > 1.5
            └─ 有 → 第三问：有 ≥ 10 个历史失效样本能拟合分布吗？
                      ├─ 没有 → CBM（先定阈值，边跑边攒样本）
                      └─ 有 → PdM（按剩余寿命排程）
```

第四种情况要补一句：**PdM 是 CBM 的升级，不是替代**。即使上了预测模型，阈值报警仍然要在，因为模型会漂移，而阈值不会。

## 三、β 是「该不该做定期维护」的唯一开关

Weibull 的形状参数 β 描述失效随时间的走势：

- `β < 1`：**早期失效型**，越用越不容易坏（或缺陷在投产初期集中暴露）。定期更换会把还能用的件换掉，**维护本身增加了失效机会**。
- `β ≈ 1`：**随机失效**，失效与已用时间无关。定期更换等于随机更换，白花钱。
- `β > 1.5`：**磨损型**，越用越容易坏。这时定期更换有效，且存在一个成本最优间隔。

本机模型读数（计划更换 `Cp = 1,200` 元、事后抢修 `Cc = 9,000` 元含停机损失、`η = 900 h`）：

| 失效分布 | 最优间隔 T | PM 单位时间费用 | 不做 PM | 结论 |
| --- | --- | --- | --- | --- |
| β = 2.2（磨损） | **350 h** | 6.29 元/h | 11.29 元/h | PM 省 **44.3%**，值得做 |
| β = 1.0（随机） | 2,000 h（边界） | 10.16 元/h | 10.00 元/h | 差 **1.6%**，等于白做 |
| β = 0.8（早期失效） | 2,000 h（边界） | 9.77 元/h | 8.83 元/h | **PM 比不做还贵 10.7%** |

::: danger 「边界解」是一个信号，不是一个答案
β ≤ 1 时最优解落在搜索区间右端（2,000 h），意思是**模型在说「别做，越晚越好」**。很多系统在这里会直接输出「建议间隔 2,000 小时」——把一个「不要做」的结论翻译成了「每 2,000 小时做一次」，方向正好相反。
:::

年龄更换模型（Age Replacement）的单位时间费用：

```text
C(T) = [Cc · F(T) + Cp · R(T)] / ∫₀ᵀ R(t) dt
```

其中 `F(T) = 1 − exp(−(T/η)^β)`、`R(T) = exp(−(T/η)^β)`，分母是一个周期内的期望运行时长。可直接跑的算法：

```python
import math

def cost_rate(T, beta, eta, cp, cc, steps=2000):
    R = lambda t: math.exp(-((t / eta) ** beta))
    f = lambda t: (beta / eta) * (t / eta) ** (beta - 1) * math.exp(-((t / eta) ** beta))
    dt, exp_len = T / steps, 0.0
    for i in range(steps):
        t = (i + 0.5) * dt
        exp_len += t * f(t) * dt
    exp_len += T * R(T)
    return (cc * (1 - R(T)) + cp * R(T)) / exp_len

for beta in (2.2, 1.0, 0.8):
    best = min((cost_rate(T, beta, 900, 1200, 9000), T) for T in range(50, 2001, 25))
    print(beta, round(best[0], 2), best[1])
# 期望输出（与本页表格一致）：
# 2.2 6.29 350
# 1.0 10.16 2000
# 0.8 9.77 2000
```

## 四、间隔的三把尺子：日历、运行小时、产量

同一个「每月一次」，在三种尺子下完全不同：

| 尺子 | 怎么写 | 什么时候用 | 坑 |
| --- | --- | --- | --- |
| 日历 | 每 30 天 | 与时间相关的劣化（油品氧化、密封老化） | 停机月份照样到期，做的是「零运行保养」 |
| 运行小时 | 每 500 h | 与磨损相关（轴承、皮带） | 需要可靠的开机计时，很多设备没有 |
| 产量 | 每 10 万件 | 与产量强相关（模具、刀具） | 改产品规格后产量口径变了，间隔跟着失真 |

::: warning 加班会把「日历间隔」悄悄改短
一台设备原设计每月运行 400 h，按「每月保养」相当于 400 h 一次。旺季每月运行 700 h，同样「每月保养」，实际变成 700 h 一次——**间隔被悄悄拉长了 75%**，而计划表上看不出任何变化。

反过来，淡季每月只开 150 h，还是「每月保养」，就是在给一台几乎没动的设备做保养。

**结论：与磨损相关的计划，间隔必须用运行小时或产量；只有与时间相关的（油品、密封、电池）才用日历。**
:::

```sql
CREATE TABLE eq_plan (
  plan_id      TEXT PRIMARY KEY,
  asset_id     TEXT NOT NULL REFERENCES eq_asset(asset_id),
  strategy     TEXT NOT NULL CHECK (strategy IN ('BM','PM','CBM','PdM')),
  basis        TEXT NOT NULL CHECK (basis IN ('CALENDAR','RUN_HOUR','OUTPUT')),
  interval_h   INTEGER NOT NULL CHECK (interval_h > 0),
  interval_out INTEGER,                     -- basis='OUTPUT' 时的产量间隔
  last_done_at TEXT,
  last_done_rh REAL,                        -- 完成时的累计运行小时
  next_due_at  TEXT NOT NULL,
  active       INTEGER NOT NULL DEFAULT 1 CHECK (active IN (0,1)),
  CHECK ( (basis = 'OUTPUT' AND interval_out IS NOT NULL)
       OR (basis != 'OUTPUT' AND interval_out IS NULL) )
);
```

`basis` 字段是这张表的灵魂。没有它，「每月一次」这句话在系统里就只是一个 `interval_h = 720`，谁也看不出它其实是按产量定的。

## 五、计划工作量要能被产能承接

间隔定得再对，做不完也等于没定。一个算例（口径演示）：

| 项 | 数值 |
| --- | --- |
| A/B 类设备 | 120 台 |
| 平均 PM 间隔 | 720 h（约每月一次） |
| 单次 PM 工时 | 2.0 h |
| 月计划工时 | 120 × 2.0 = **240 人时** |
| 可用维修人力（3 人 × 8 h × 22 天 × 0.7 效率） | **369 人时** |
| 计划占用率 | **65%** |

剩下的 35% 要承接纠正性维修与突发。**占用率超过 80% 时，PM 一定会被推迟，而推迟的 PM 在报表上仍显示「计划中」**——这是「计划完成率」这个指标最常见的失真来源。

::: tip 一个可执行的阈值
计划占用率 > 80% 时，先做两件事之一：把部分 B 类设备的间隔按 β 重新算（很可能本来就不该这么密），或者把 PM 拆成「必做项 / 可延项」两档。不要用「加班」解决，加班会把纠正性维修的响应时间挤掉。
:::

## 六、从 CBM 到 PdM 的门槛

| 门槛 | 具体要求 | 达不到会怎样 |
| --- | --- | --- |
| 样本量 | 同一设备类别 ≥ 10 个完整失效样本（含删失数据） | β 估计的置信区间跨过 1，结论不可用 |
| 征兆可测 | 失效前至少有一个测点出现单调趋势 | 模型只能学到噪声 |
| 时间窗 | 从报警到失效的时间 > 一次备件采购提前期 | 预测到了也来不及 |
| 反馈闭环 | 每次拆检结果要回写「预测对不对」 | 阈值永远停在初始值 |

第 4 条最容易被跳过。没有回写，CBM 的阈值就是「上线那天拍的那个数」，跑三年也不会变准。

## 七、判据清单

| 编号 | 判据 | 怎么验 |
| --- | --- | --- |
| `EQS-A` | 每台 A/B 类设备都有策略，且策略 ∈ {BM, PM, CBM, PdM} | 无 `strategy IS NULL` 的 A/B 类设备 |
| `EQS-B` | 磨损类计划的 `basis` 是 `RUN_HOUR` 或 `OUTPUT`，不是 `CALENDAR` | 按 `basis` 分组统计 |
| `EQS-C` | 每个 PM 间隔能追溯到 β 估计或厂家依据 | `eq_plan` 有 `basis_ref` 或校准记录 |
| `EQS-D` | β < 1 的设备不存在「定期更换」型计划 | 交叉查询失效分布表与计划表 |
| `EQS-E` | 计划占用率可按月计算，且 > 80% 时告警 | 有 `pm_load` 视图 |
| `EQS-F` | CBM 阈值有来源（标准 / 厂家 / 历史分位）与复核日期 | `threshold_src` + `threshold_checked_at` |
| `EQS-G` | PdM 上线前有 ≥ 10 个失效样本，否则标记为 CBM | `model_ready` 标记与样本计数一致 |
| `EQS-H` | 间隔变更留痕（旧值 / 新值 / 依据 / 人） | 有 `plan_change_log` |

## 八、验证方式

```shell
# 1) 磨损类计划不应按日历定间隔
sqlite3 /tmp/mnt.db "SELECT count(*) FROM eq_plan p JOIN eq_asset a USING(asset_id)
                      WHERE a.criticality IN ('A','B') AND p.basis='CALENDAR';"
# 期望：0（或仅为油品/密封类，需逐条说明）

# 2) 间隔必须为正，且 OUTPUT 类必须有产量间隔
sqlite3 /tmp/mnt.db "SELECT count(*) FROM eq_plan WHERE interval_h <= 0
                      OR (basis='OUTPUT' AND interval_out IS NULL);"
# 期望：0

# 3) 计划占用率（示例口径：月计划工时 / 月可用工时）
sqlite3 /tmp/mnt.db "SELECT ROUND(1.0*count(*)*2.0/(3*8*22*0.7),3) FROM eq_plan WHERE active=1;"
# 期望：< 0.80；超过则先重算间隔再谈执行

# 4) 最优间隔的模型复算（与页面表格对得上）
python3 - <<'PY'
import math
def rate(T,b,e,cp,cc,n=2000):
    R=lambda t: math.exp(-((t/e)**b)); f=lambda t:(b/e)*(t/e)**(b-1)*math.exp(-((t/e)**b))
    dt=T/n; L=sum((i+0.5)*dt*f((i+0.5)*dt)*dt for i in range(n))+T*R(T)
    return (cc*(1-R(T))+cp*R(T))/L
print(min((round(rate(T,2.2,900,1200,9000),2),T) for T in range(50,2001,25)))
PY
# 期望：(6.29, 350)
```

::: warning 别把模型输出当决策
`C(T)` 模型只回答「在给定 Cp、Cc、β 下哪个间隔最便宜」。它不回答「停机损失到底是多少」——那个数往往要财务与生产一起定。模型跑得再准，输入错了也是错的。
:::
