# 设备维护与可靠性

<p style="text-align:center;"><img src="./assets/em-logo.png" alt="设备维护与可靠性工程" style="zoom:75%;" /></p>

车间里最容易被糊弄的一句话是「**设备没坏**」。它没说谎，也没说全——设备在转，但它已经在振动上预警了三个月、在点检表上漏了十二天、在备件库房里欠着一个没有安全库存的轴承。维护要回答的不是「坏没坏」，而是**它下一次什么时候停、会停多久、现在动手和等它坏了再动手哪个更便宜**。

::: tip 一句话理解
**设备维护不是「坏了去修」，而是拿「停机时长 × 停机代价」去换「维护工时 × 备件库存」的一笔连续交易。** 交易做得好不好，只能用三个数说话：可用率、平均无故障间隔、单位时间维护成本。
:::

## 这个专题讲什么

一台设备从「进厂登记」到「退役拆解」要过七道环节。本专题按这七段组织，每段都标出产物与失败方式：

| 段 | 这一段在做什么 | 产物 | 失败是否安静 |
| --- | --- | --- | --- |
| ① 建 | 给「东西」和「位置」各编一个号，定关键性 | 台账 + 功能位置树 | **安静**（少建一层，后面所有汇总都错） |
| ② 定 | 决定每台设备用哪种维护策略、间隔多长 | 维护计划 + 到期日 | **安静**（间隔定错，只会表现为「维护了还是坏」） |
| ③ 检 | 点检与状态监测，判断「还撑得住吗」 | 测点 + 记录 + 判定 | **安静**（补录也显示完成率 100%） |
| ④ 修 | 报修、派工、开工、完工、关单 | 工单 + 停机区间 | 半显性（关单要填完工时间） |
| ⑤ 备 | 备件储备、领用、可修复件循环 | 库存 + 领用流水 | **安静**（缺件才知道，且只在最贵的时候知道） |
| ⑥ 算 | 停机口径、可用率、OEE 分解 | 报表 | 半显性（口径不写清，两个部门永远差） |
| ⑦ 验 | 用失效数据校核 β、间隔与冗余假设 | 可靠性参数回写策略 | **安静**（不回写，等于每年重复同一个错误决定） |

![七段维护链：从「建台账」到「校核可靠性」](./assets/em-chain.svg)

七段里**五段的失败是安静的**。它们不会报错、不会挡住任何人，只会让年底那张「设备综合效率」报表变成一个谁也解释不清的数。而唯一会当场报错的第 ④ 段，恰恰是最容易被「先干完活再补单」绕过去的一段——补完的单上没有真实的开工时刻，MTTR 从此不可信。

## 三个「好了」，只有一个是维护的

| 说法 | 谁在说 | 证据是什么 | 与维护的关系 |
| --- | --- | --- | --- |
| 工单关了 | 维修班组 | `state = CLOSED` | 只是动作结束，可能是「暂时能转」 |
| 设备转起来了 | 生产班组 | 现场看得到 | 只是当前状态，不代表下次不坏 |
| 不会再这样坏 | 维护工程 | β、间隔、备件、冗余四件事同时成立 | **这才是维护的产出** |

前两个可以靠补单补齐，第三个补不了。所以本专题所有页面的判据，都尽量落在「**能被下一次失效检验**」的形态上，而不是「有没有做」。

库里写「设备」的册子不止一本，问的问题却完全不一样。先看这张表再决定读哪一册：

| 你关心的问题 | 该读哪一册 | 为什么不是本册 |

| 「这批货做完了没有、良品多少」 | [生产执行与工单报工](../Manufacturing/Overview/index.md) | 那册判**数量守恒**，本册判**停机时长** |
| 「这次停机让成本多了多少」 | [成本核算与月末结账](../CostAccounting/Overview/index.md) | 那册管**金额归集**，本册只提供时长与原因 |
| 「料在哪个货位、谁去拣」 | [仓储作业与波次拣选](../WarehouseOps/Overview/index.md) | 那册管**库内空间与路径**，本册管**备件够不够** |
| 「采购单什么时候到货」 | [采购到付款](../ProcureToPay/Overview/index.md) | 那册管**三单匹配**，本册只取「备件到货期」这一端 |
| 「设备故障算不算事故、怎么取证」 | [事故响应与值班](../../Ops/IncidentResponse/Overview/index.md) | 那册管**一次事件的组织响应**，本册管**设备一生的失效规律** |
| 「维护工单的审批流怎么走」 | [工作流引擎](../WorkflowEngine/Overview/index.md) | 那册管**流程编排**，本册管工单的**状态与时长口径** |
| 「备件采购的钱怎么算」 | [资金管理](../Treasury/Overview/index.md) | 那册管**现金时点**，本册管**库存水平** |
| 「物料编码怎么统一」 | [主数据与标准](../../DB/DataGovernance/StandardsMasterData/index.md) | 那册管**编码规则**，本册管**设备层级与编号归属** |
| 「产能成本怎么算单位成本」 | [容量与成本](../../Ops/CapacityCost/Overview/index.md) | 那册管**单位成本曲线**，本册管**可用率对产能的折损** |

::: info 为什么不并入「资产台账与折旧摊销」
两册共用同一份设备清单，但判据一条都不重合：资产册判「**账实相符**」——台账上的原值、累计折旧、净值能不能对上总账；本册判「**可用性可算**」——同一台设备的停机区间并起来是几个小时、这些小时落在哪个原因上。

一台设备可以账实完全相符（原值对、折旧对、盘点在），同时可用率从 99% 掉到 81%，而账上一点异常都没有——因为停机不是会计事件。反过来，一台设备可以天天停机但账实不符到无法盘点。一个判钱，一个判时间；合并只会造出第二个「基础 + 进阶」的注水章节。
:::

## 判据族与页面对应

本专题共 **10 族 80 条判据**，每页 8 条，逐页独立、不跨页复用：

| 页面 | 判据族 | 这一族在判什么 |
| --- | --- | --- |
| 总览 | `EQM-A` ~ `EQM-H` | 七段是否齐全、三个「好了」是否分开记 |
| 台账 | `EQA-A` ~ `EQA-H` | 位置与设备是否分开编号、停机能否向上汇总 |
| 策略 | `EQS-A` ~ `EQS-H` | 策略是否由失效分布决定、间隔是否有依据 |
| 点检 | `EQC-A` ~ `EQC-H` | 测点是否有判定、补录是否可识别 |
| 工单 | `EQW-A` ~ `EQW-H` | 状态迁移是否受限、停机是否挂上工单 |
| 备件 | `EQP-A` ~ `EQP-H` | 安全库存是否按服务水平算、呆滞是否可见 |
| 停机 | `EQD-A` ~ `EQD-H` | 分母是否写明、区间是否取并集 |
| 可靠性 | `EQR-A` ~ `EQR-H` | 参数是否带样本量、冗余是否计共因 |
| 实战 | `EQX-A` ~ `EQX-H` | 七表闭环能否一次跑通、负向用例是否被拒 |
| 分诊 | `EQQ-A` ~ `EQQ-H` | 现象能否定位到段、口径争议能否当场判 |

::: warning 判据不是清单，是「能被下一次失效检验的断言」
`EQD-C` 写的是「停机报表必须同时给出三个分母」，不是「记得写清楚口径」。前者可以被一条 SQL 判定，后者只能靠自觉。本专题每条判据都尽量写成前者。
:::

## 事实与规格速览（2026-11 核对）

| 项 | 现行口径 | 备注 |
| --- | --- | --- |
| 资产管理体系 | ISO 55000:2024 / ISO 55001:2024 | 2014 版已作废；`55002:2018` 仍在用，第 3 版在编 |
| 维护术语 | EN 13306:2017 | 纠正性 / 预防性 / 状态维护的定义边界 |
| 可靠性数据 | ISO 14224:2016（2022 复核确认） | 设备分类、失效模式、维修数据的「可靠性语言」 |
| 状态监测程序 | ISO 17359:2018（2023 复核确认） | 是**流程**标准，不含具体限值 |
| 振动评价 | ISO 20816-3:2022 | 取代 ISO 10816-3:2009 与 ISO 7919-3:2009，A/B/C/D 四区 |
| 维修指标 | SMRP 指标体系 | 常用：可用率、MTBF、MTTR、计划维护占比、维护成本占重置资产比 |

::: danger 版本事实有保质期
上表每一行都会在几年内过期。写进系统配置时，**必须把标准号与核对日期一起落库**（例如 `standard_ref = 'ISO 20816-3:2022'`、`checked_at = '2026-11-02'`），否则三年后没人知道这个阈值是按哪一版定的。
:::

## 为什么本专题不建版本目录

本专题**不设** `V1/`、`V2/` 这类版本目录。三条理由：

1. **换代的是标准编号与仪表，不是判据**：ISO 10816-3 换成 ISO 20816-3，换的是分区边界与人拿哪本手册，而「振动值越过 C 区就该安排检修」这条判断一字未变。
2. **并存的差异是行业与设备类型，不是代际**：石化按 ISO 14224 收数据、离散制造按件报工、物业按工单计费，三者是同一套判据的不同参数，不是两套内容线。
3. **真正需要版本目录的是「同一份代码两套写法」**：库内按大版本组织的先例是 [Spring5](../Java/Frame/Spring/Spring5/index.md) 与 [Spring6](../Java/Frame/Spring/Spring6/index.md)、[Vue2](../../Frontend/Frame/Vue/Vue2/index.md) 与 [Vue3](../../Frontend/Frame/Vue/Vue3/index.md)——那是同一框架的两代 API 并存，旧版本必须保留并标注维护状态。本专题写的是单据模型与统计口径，不存在两代并存的问题。

涉及外部依据时，本专题引用**标准编号 + 现行版本**，并在正文里说明该版本相对上一版改了什么（例如振动标准的四区划分与量程变化），而不是复制一份会过期的表格当结论。
