# 常见问题与分诊

<p style="text-align:center;"><img src="../assets/em-logo.png" alt="设备维护与可靠性工程" style="zoom:75%;" /></p>

设备管理的问题几乎从不是「不知道怎么做」，而是「**现象看起来像 A，其实是 F**」。这一页先给一张分诊表，再回答十二个高频问题，最后是上线自查清单与术语表。

本页判据族 `EQQ-A` ~ `EQQ-H`，共 8 条，定义在第六节。

## 一、现象分诊表

先看现象落在哪一段，再决定翻哪一页。分诊第一问永远是「**这个数的分母是什么**」，第二问是「**它是不是并集**」。

| 现象 | 先跑什么 | 翻哪一页 | 最常见的真因 |
| --- | --- | --- | --- |
| 设备总在同一时间停 | 按小时统计停机分布 | [维护策略](../Strategy/index.md) | 间隔按日历定，旺季实际被拉长 |
| 点检表全绿但仍突然坏 | 查补录率与测点覆盖 | [点检](../Inspection/index.md) | 补录 + 测点选在没有征兆的位置 |
| 工单很多但停机不长 | 查去重键 | [工单](../WorkOrder/index.md) | 同一故障被多次上报，单量虚高 |
| 停了很久在等件 | 查 ABC 与安全库存 | [备件](../SpareParts/index.md) | 关键件零库存，或按金额分类漏掉关键件 |
| 两个部门可用率不一致 | 查分母与并集 | [停机口径](../Downtime/index.md) | 一个用日历、一个用负荷；一个求和、一个并集 |
| 换了新件反而更爱坏 | 查 β 与安装质量 | [可靠性](../Reliability/index.md) | β < 1 的件被「定期更换」，或安装力矩不对 |
| MTBF 报表一年比一年好 | 查短停是否被过滤 | [可靠性](../Reliability/index.md) | 采集粒度变粗，短停消失 |
| 保养做了但故障没降 | 查计划占用率与执行率 | [维护策略](../Strategy/index.md) | 占用率 > 80%，PM 被推迟却仍标「计划中」 |
| 备件库越堆越多还缺件 | 查二维分类（金额 × 关键性） | [备件](../SpareParts/index.md) | 按金额分类，关键件落在 C 类没人管 |
| 停机总时长对不上财务损失 | 查换型归类与计划停机 | [停机口径](../Downtime/index.md) | 换型算不算停机，两边定义不同 |
| 设备台账与财务台账对不上 | 查四个号的对齐关系 | [台账](../AssetRegister/index.md) | 设备号 = 资产号，大修拆分后失联 |
| 上系统后数据更乱了 | 查「先别上系统」五问 | [总览](../Overview/index.md) | 口径没定就上系统，把混乱搬进数据库 |

## 二、十二个高频问题

### 2.1 我们没有失效数据，能算 MTBF 吗？

能，但只能算「粗略的 MTBF」：`运行时间 / 工单数`。前提是工单数可信——也就是去重键已经生效（否则单量虚高，MTBF 偏小）。**没有 `failure_mode` 时不要算 β**，不同失效模式混在一起拟合出来的 β 没有物理意义。

### 2.2 一台设备应该做几种维护策略？

通常两种：主策略 + 兜底。例如「CBM 为主 + BM 兜底」（有监测但没测到的失效仍按坏了再修）。**一台设备只做 PdM 是危险的**，因为模型会漏；只做 BM 对 A 类设备是赌博。

### 2.3 「每月保养一次」到底错在哪？

错在它没有单位。同样的「每月」，在运行 400 h 的淡季是 400 h 一次，在运行 700 h 的旺季是 700 h 一次——**间隔被悄悄改变了 75%，而计划表上看不出任何变化**。与磨损相关的计划必须用运行小时或产量。

### 2.4 备件到底备多少？

先分二维：**金额 ABC × 关键性 ABC**。金额 A + 关键性 A 的件按服务水平算安全库存（`SS = z·σ_d·√L`）；金额 C 但关键性 A 的件单独列一张表，按停机损失倒推。其余用「定量订货 + 允许缺货」。

### 2.5 为什么服务水平从 95% 提到 99%，总成本反而降了？

因为停机损失远大于库存持有成本。本机算例：库存多花 4,936 元，少停 58,867 元的机。**这条结论只在「停机损失 ≫ 持有成本」时成立**，便宜的 C 类件不适用。

### 2.6 OEE 多少算好？

不要问绝对值，先问三个口径：分母是日历还是负荷？换型算不算停机？性能的分母是铭牌还是历史最佳？三个口径不同，同一个车间能差 15 个百分点（84.66% vs 69.43%）。**跨厂比较 OEE 之前必须先对齐这三条。**

### 2.7 冗余能解决可用率问题吗？

只对独立失效有效。两台泵并联在独立假设下 99.00%，计 2% 共因后 98.82%。**共因那部分不随冗余数量下降**——所以先问「这两台共用什么」，再谈备几台。

### 2.8 点检完成率 98% 为什么还出事？

因为完成率只证明「有记录」。要同时看两个数：**交班前 10 分钟的集中度**（本机 63.4%）与**连续未检空档**（本机最长 12 天）。前者高、后者有，说明这张表是补出来的。

### 2.9 MTBF 和 MTTR 哪个更该改？

看瓶颈在哪。若 MTTR 的构成里「等件」占 40%，改 MTBF（更可靠）没用，要改备件；若「诊断」占大头，要改故障树与经验库；若「响应」占大头，要改值班与派工。**先拆四段，再决定改哪段。**

### 2.10 设备台账要不要把部件也建进去？

只在两种情况下建：需要**单独记寿命**（轴承、密封、伺服阀），或需要**单独备件**。否则设备总数会从 200 涨到 3,000，可用率分母直接失真。

### 2.11 「先修好，单子明天补」到底能不能接受？

能，但必须满足两条：① 补录时填**真实起止时刻**而不是录入时刻；② 标记 `backfilled = 1`。做不到这两条，MTTR、班次归属、等件时长会同时失真，而且没人能发现。

### 2.12 什么时候该从 CBM 升级到 PdM？

四个门槛同时满足：同类设备 ≥ 10 个完整失效样本、失效前有单调征兆、报警到失效的时间 > 备件提前期、拆检结果能回写。**少一条就还是 CBM。**

## 三、八个常见误区

::: danger 误区一：把「可用率高」当成「维护好」
可用率高可能只是因为分母大（日历口径把不排产的时间也算进去了）。同一批数据，日历口径 81.75%、负荷口径 99.70%。
:::

::: danger 误区二：把「工单关闭率」当成执行力
关闭率可以通过「快速关单」刷高。要看的是**重开率**与**补单率**，这两个数刷不上去。
:::

::: danger 误区三：认为「定期更换一定比坏了再修好」
`β < 1` 时定期更换比不换更贵（本机 9.77 vs 8.83 元/h），因为它把还能用的件换掉了，同时引入了安装失效风险。
:::

::: danger 误区四：用「平均故障间隔」比较不同设备
不同设备的关键性、运行强度、工况完全不同。MTBF 只能纵向比（同一台设备的趋势），横向比要先做工况归一。
:::

::: danger 误区五：把停机时长直接求和
同一设备的并发归因会让求和比并集多 9.1%（本机 285,172 vs 259,102），足以改变「停机最多的前五台」排序。
:::

::: danger 误区六：认为「备件越全越好」
库存是现金。13 个零动支 SKU 占压 117,239 元；关键是区分「设备还在运行的关键件」与「设备已退役的遗留件」，前者留、后者清。
:::

::: danger 误区七：用「总停机小时」考核维修班组
总停机里有等件、有生产安排、有换型。只考核总时长，班组会把等件时间记成「其他」——而「其他」这一项通常没人分析。
:::

::: danger 误区八：先上系统再定口径
系统的第一件事是把口径固化。口径没定就上线，等于把混乱写进数据库，而且以后再改要迁移历史数据。
:::

## 四、上线自查清单（20 项）

**台账与分级**

1. 功能位置与设备是两个号，且位置有层级。
2. 关键性分级按四维取短板，且有文字理由。
3. A 类设备清单已确认，且数量在 10~30 台之间（太多说明分级失效）。
4. 换机新建号、旧号置 `RETIRED` 已写进制度。

**计划与执行**

5. 每台 A/B 类设备都有策略，且策略不是全厂一个值。
6. 磨损类计划的间隔单位是运行小时或产量，不是日历。
7. 计划占用率已计算，且 < 80%。
8. 近一年至少有一条计划因失效数据被改过间隔。

**点检与监测**

9. 每条点检记录有测点、指标、数值、判定。
10. 补录率已统计，且 < 40%。
11. 连续未检空档可查询，最长 < 7 天。
12. 阈值有来源（标准 / 厂家 / 历史分位）与复核日期。

**工单与停机**

13. 报修有去重键，且唯一。
14. 同一设备不允许两条未闭合停机。
15. 已关闭的纠正工单都有停机记录。
16. 关单后不可回退。
17. 停机区间按并集计算，且报表标注分母。

**备件与可靠性**

18. 备件有金额 ABC 与关键性两维分类。
19. 关键件安全库存按服务水平算，有 `service_lvl`。
20. MTBF 报表同时给出「含短停 / 不含短停」两行。

## 五、术语表

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 功能位置 | Functional Location | 「装在哪」，不随设备更换而变 |
| 关键性 | Criticality | 失效后果的等级，按短板取 |
| BM | Breakdown Maintenance | 坏了再修 |
| PM | Preventive Maintenance | 按时间或产量定期做 |
| CBM | Condition Based Maintenance | 按测点阈值触发 |
| PdM | Predictive Maintenance | 按剩余寿命预测排程 |
| MTBF | Mean Time Between Failures | 平均故障间隔 |
| MTTR | Mean Time To Repair | 平均修复时间（含等待） |
| MTTF | Mean Time To Failure | 不可修件的平均寿命 |
| 可用度 | Availability | 可工作 / 应工作，分母必须写明 |
| OEE | Overall Equipment Effectiveness | 可用率 × 性能 × 质量 |
| β | Weibull shape | 失效趋势：<1 早期、≈1 随机、>1 磨损 |
| η | Weibull scale | 特征寿命，此时可靠度 36.8% |
| 右删失 | Right Censoring | 到统计日仍运行，只知寿命下界 |
| 共因失效 | Common Cause Failure | 一个原因同时打掉冗余的两路 |
| 并集时长 | Union Duration | 重叠区间只算一次的总时长 |
