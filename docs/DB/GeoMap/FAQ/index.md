# 常见问题与分诊

这一页按「现象 → 先跑什么 → 翻哪页 → 最常见真因」组织。地图类问题的特点是**都不报错**，所以第一步永远不是改代码，而是**确定它属于哪一类错**。

::: tip 一句话理解
先分清「整体偏」还是「个别偏」，再分清「查不到」还是「查得慢」——四象限一定，答案基本就出来了。
:::

![四象限分诊：从现象到真因的最短路径](../assets/gm-faq-triage.svg)

## 一、症状分诊表

| 现象 | 先跑什么 | 翻哪页 | 最常见真因 |
| --- | --- | --- | --- |
| 所有点整体偏几百米，方向一致 | 用一个已知地标打点比对 | [坐标系](../CRS/index.md) | 数据是 GCJ-02，底图是 WGS84（或反之） |
| 只有一部分点偏 | 按 `src_crs` 分组统计 | [坐标系](../CRS/index.md) | 某个批次来源坐标系没标注 |
| 点整体在正确位置，但**南北颠倒** | 直接请求 `z=1` 的瓦片看方向 | [瓦片](../Tiles/index.md) | XYZ 与 TMS 的 y 轴反了 |
| 查「附近」返回全表 | 看半径参数与几何类型 | [查询](../Query/index.md) | 在 4326 几何上用度数当米 |
| 加了索引还是很慢 | `EXPLAIN ANALYZE` 看 recheck 行数 | [建模与索引](../Modeling/index.md) | 外包框不贴合 / 谓词被函数包住 |
| 边界上的人反复进出 | 看是否有滞回带与状态机 | [围栏](../GeoFence/index.md) | 只做了「在不在里面」，没做边沿触发 |
| 打卡记录重复 | 查事件表唯一键 | [围栏](../GeoFence/index.md) | 缺 `(device, fence, seq)` 幂等键 |
| 地图打开慢、首屏空白久 | 数首屏请求的瓦片块数 | [瓦片](../Tiles/index.md) / [渲染](../Render/index.md) | 初始 zoom 太高 / 瓦片体积过大 |
| 点击要素没反应 | `queryRenderedFeatures` 手动查 | [渲染](../Render/index.md) | 命中框 1 px / 图层被遮挡 |
| 数据更新了但页面还是旧的 | 看瓦片 URL 是否带版本 | [瓦片](../Tiles/index.md) | 只有 TTL 没有版本号 |
| 高倍缩放时折线变折角 | 看每级简化容差 | [瓦片](../Tiles/index.md) | 所有层级用了同一个容差 |
| 面积/距离算出来偏大 | 看几何所在 SRID | [坐标系](../CRS/index.md) | 在 3857 上直接算，没做 `cos(lat)` 修正 |

## 二、高频十二问

### Q1 经纬度存两个 `double` 列不行吗？

能存，但**查询会退化成矩形范围扫描**，且没有类型约束保护（`lat=116` 也能存进去）。只要有「附近 / 范围 / 距离」需求，就该用 `geometry` 或 `geography`。

### Q2 `geometry` 与 `geography` 到底怎么选？

要**米**且只要距离/包含 → `geography`；要**缓冲、简化、面积、投影** → `geometry`。混用方案（存 geometry，查询时 `::geography`）在实践中最好用，索引也仍然生效。

### Q3 为什么 `ST_DWithin(a, b, 1000)` 返回了全表？

因为 `a`、`b` 是 `geometry(4326)`，`1000` 的单位是**度**。加 `::geography` 或改用米制投影。

### Q4 `ST_Contains` 和 `ST_Covers` 差一个边界点，为什么这么重要？

因为边界恰好是争议发生的地方：考勤、计费、区域归属统计。**必须在文档里写死选哪个**，并用一条边界用例锁住。

### Q5 空间索引建了为什么不走？

三种可能：谓词把列包进了函数（`ST_Distance(geom, …) < r`）、查询的选择性太差（返回全表 30% 以上，优化器宁愿顺序扫）、统计信息过期（`ANALYZE` 没跑）。

### Q6 为什么 `ORDER BY geom <-> pt` 很快，`ORDER BY ST_Distance` 很慢？

前者是 GiST 的**有序扫描**，取够 n 行就停；后者要算全表距离再排序。

### Q7 瓦片编号为什么不能跨投影复用？

`(z, x, y)` 隐含了「3857 + 256 px + 左上原点」三个约定。换投影后同一个编号指向另一块地面，缓存全部失效——所以正确做法是**换版本号**，而不是原地覆盖。

### Q8 矢量瓦片和 GeoJSON 怎么选？

要素少于几千、需要频繁改属性 → GeoJSON 够用；要素多、需要按 zoom 分层简化 → 矢量瓦片。两者的分界不在数据量本身，而在**是否需要「分级细节」**。

### Q9 轨迹点要不要全存？

**要**。原始点是唯一能重算的证据；简化结果只是物化视图。抽稀能压到 3% 左右（5 m 容差），但那是「展示用」，不是「唯一副本」。

### Q10 围栏半径设 30 m 行不行？

多数场景不行。城市 GPS 误差常在 5~20 m，高楼区更大；半径小于 `2 × accuracy` 时，静止的人也会反复进出。要么放大半径，要么加滞回带与持续时间。

### Q11 用 OSM 底图对外发布中国地图可以吗？

不建议直接使用：国界与行政区域界线的表示需符合国内规范，应使用标准地图服务或有资质的服务商底图。见[合规](../Compliance/index.md)。

### Q12 离线包怎么保证不过期？

包内带 `source.json`（来源、审图号、规范版本、`expire_at`），客户端启动校验；规范本身有 5 年有效期，换版时旧包要能停用。

## 三、八个必须纠正的误区

::: danger 误区一：地图上看起来对齐了，就是对的
视觉对齐只能排除「粗差」。几百米的系统偏移在市级缩放级别下**几乎看不出来**，但在门牌级就是「送到隔壁小区」。判据必须是坐标数值比对，不是肉眼。
:::

::: danger 误区二：`SRID` 只是元数据，不影响结果
它决定**单位**。4326 的单位是度，3857 是米（被放大的米）。同一个 `1000`，含义完全不同。
:::

::: danger 误区三：索引能解决一切慢查询
索引只按**外包框**排除。一条对角线走向的长条查询，外包框可能覆盖整城，候选放大 10~25 倍（本机实测，见[建模与索引](../Modeling/index.md)）。这时要改查询形状，不是加索引。
:::

::: danger 误区四：`ST_Buffer(geom, 5000)` 就是 5 公里
在 4326 几何上是 5000 **度**。必须 `::geography` 或先投影。
:::

::: danger 误区五：抽稀是「无损压缩」
1. 它改变几何，不是压缩。抽稀只保留「形状」，丢掉的是**位置**。
2. 用于展示可以；用于里程统计会系统性偏小——本机实测 20 m 容差只剩 0.17% 的点，1000 个点压成 2 个，里程几乎归零。
3. **正确做法**：里程、面积、停留判定一律用原始点逐段累加；抽稀产物只进渲染图层，且带一个 `simplified=true` 标记防止被下游误用。
:::

::: danger 误区六：瓦片缓存用 CDN 就万无一失
CDN 缓存的是 URL。URL 不带版本，就等于**把旧数据固定住**；URL 带签名，就无法共享缓存。两者只能选一个，通常选版本化路径。
:::

::: danger 误区七：合规是法务的事
审图号、精度上限、禁止表示的要素，最终都落在**数据与样式**上，法务改不了你的 SQL。工程侧必须有一张「类别 → 是否可公开」的映射表。
:::

::: danger 误区八：地图组件换个 `center` 就能修偏移
偏移是全链路的坐标系问题。改 `center` 只会让「一部分点看起来对了」，另一部分更错。
:::

## 四、上线前 20 项自查清单

**数据层**

1. 每条空间记录有可追溯的来源坐标系。
2. 主几何列有 typmod（`geometry(Point, 4326)`）。
3. 经纬度范围有 `CHECK` 约束。
4. 非法几何（自相交、未闭合）有盘点与处置记录。
5. 坐标小数位与业务精度匹配（4~6 位）。

**查询层**

6. 高频查询走 `Index Scan`。
7. 距离半径使用米制类型（`geography` 或投影）。
8. 边界归属写死并有边界用例。
9. 最近邻用 `<->`，不用 `ORDER BY ST_Distance`。
10. 分页有唯一二级排序键。

**出图层**

11. 瓦片编号体系（XYZ/TMS）与服务一致。
12. `extent` / `buffer` 写在配置里。
13. 简化容差按层级配置。
14. 瓦片 URL 含版本号，空瓦片返回 200 + 空 MVT。
15. 底图与业务数据坐标系一致；有审图号可见。

**交互与运维**

16. 命中容差 ≥ 12 px，触控目标 ≥ 44 px。
17. 选中用 `feature-state`，不全量 `setData`。
18. 有首屏时间与 p95 延迟的基线。
19. 围栏事件有幂等键与边沿触发。
20. 合规自查清单 8 项全过。

## 五、本页判据

本页判据族 `GMX-A` ~ `GMX-H`，共 8 条，针对「分诊过程本身是否可信」。

| 编号 | 判据 | 判定方式 | 不满足时改哪里 |
| --- | --- | --- | --- |
| `GMX-A` | 每个线上问题都能归入四象限之一 | 事故记录里有「现象 → 象限」字段 | 补分诊表条目 |
| `GMX-B` | 分诊第一步是「取证据」而不是「改代码」 | 排查记录里有命令与输出 | 见第一节「先跑什么」 |
| `GMX-C` | 偏移类问题有已知地标的回归用例 | 用例里有地标坐标 | 补用例；这是最快的判据 |
| `GMX-D` | 慢查询问题有 `EXPLAIN` 证据 | 工单附计划截图或文本 | 补证据；否则改不动 |
| `GMX-E` | 每个坑都能指到「本专题的哪一节」 | 表格第四列非空 | 补交叉引用 |
| `GMX-F` | 术语表与库内其他专题的用法一致 | 与 `DB/FullTextSearch` 等页的术语无冲突 | 统一用词 |
| `GMX-G` | 清单项都可机械核对（命令或查询） | 每一项能写出判据 | 改写不可核对的项 |
| `GMX-H` | 误区条目来自真实事故而不是想象 | 每条能指出发生过的场景 | 删掉没发生过的条目 |

## 六、术语表

| 术语 | 含义 | 易混点 |
| --- | --- | --- |
| 地理坐标系 | 用经纬度表示位置 | 单位是度，不是米 |
| 投影坐标系 | 把球面投到平面，单位常为米 | 3857 的米被放大 |
| SRID | 空间参考系编号 | 0 表示未知，不等于 4326 |
| 外包框（bbox） | 几何的最小外接矩形 | 索引只认它，不认精确形状 |
| 瓦片（tile） | 固定尺寸的地图分块 | 编号隐含投影与尺寸 |
| MVT | Mapbox 矢量瓦片格式 | 整数坐标 + extent |
| 围栏（geofence） | 一个区域 + 触发规则 | 光有多边形不算围栏 |
| 滞回（hysteresis） | 进出用不同阈值形成的死区 | 没有它必然抖动 |
| 等时圈 | 一定通行时间内可达的范围 | 与缓冲区不是一回事 |

## 七、验证方式

```shell
# 偏移类问题的 60 秒判据：打一个已知地标，看落点
# 天安门 ≈ 116.3975, 39.9087（WGS84）
curl -s "https://<域名>/api/nearby?lng=116.3975&lat=39.9087&r=200" \
  | python -c "import json,sys;d=json.load(sys.stdin);print(len(d.get('items',[])))"
# 预期：能返回该点附近的门店；返回 0 且地图上看着「有店」，说明坐标系错

# 慢查询：先看计划，再改写法
psql -c "EXPLAIN (ANALYZE, BUFFERS) SELECT id FROM poi
         WHERE ST_DWithin(geom::geography, ST_SetSRID(ST_MakePoint(116.3975,39.9087),4326)::geography, 1000);" \
  | head -12
# 预期：Index Scan；若出现 Seq Scan，先查谓词写法
```
