# HTML 语义化标签

**概念**：用特定的标签，去表达特定的含义 (根据内容的结构和含义选择恰当的HTML元素)。

**原则**：标签的默认效果不重要（后期可以通过CSS 随便控制效果），语义最重要！

**例**：对于h1 标签，效果是文字很大 (不重要)，语义是网页主要内容 (很重要)。

**优势**：

- 代码结构清晰可读性强。
- 有利于 SEO (搜索引擎优化)。
- 方便设备解析 (如屏幕阅读器、盲人阅读器等)。

## 语义化到底解决了什么

上面第三条「方便设备解析」是最容易被忽略、也最有实际收益的一条。**屏幕阅读器不带眼睛，它读的是浏览器生成的无障碍树**——而这棵树的长相，几乎完全由你选的元素决定。

| 你写的 | 浏览器生成的无障碍树 | 读屏实际播报 |
| --- | --- | --- |
| `<button>提交</button>` | role=button，name=提交，可聚焦 | 「提交 按钮」，Tab 能到、回车能激活 |
| `<div class="btn">提交</div>` | 无角色，不可聚焦 | 只有线性读到时念出「提交」，Tab 完全到不了 |
| `<h2>文章列表</h2>` | role=heading，level=2 | 「文章列表 二级标题」，可按 H 键跳转 |
| `<div class="title">文章列表</div>` | 无角色 | 念出「文章列表」，但没有标题语义，无法跳转 |

所以语义化的收益是三层叠加的：**可读的代码结构 → 可抓取的 SEO 结构 → 可操作的无障碍结构**。前两条有替代方案，第三条没有——用 `div` + CSS 能做出视觉上一模一样的按钮，但做不出键盘可达性。

::: tip 一句话判据
**把 CSS 关掉，只看 HTML：这一页还能读懂、还能操作吗？** 能，说明语义放对了位置；不能，说明你把语义写进了 CSS 与事件里。
:::

## 语义化元素速查

| 想表达的东西 | 优先用 | 不要用 |
| --- | --- | --- |
| 可点击按钮 | `<button type="button">` | `<div>` / `<span>` + click |
| 页面跳转 | `<a href="...">` | `<div>` + 路由跳转 |
| 分组标题（表单内） | `<fieldset>` + `<legend>` | `<div class="group-title">` |
| 折叠面板 | `<details>` + `<summary>` | `<div>` + 显隐切换 |
| 弹窗 | `<dialog>` | `<div class="modal">` |
| 进度 | `<progress>` | 纯 CSS 动画 |

完整的判据、ARIA 五条规则与可访问名称的计算顺序，见 [国际化与无障碍 · 无障碍基础](../../../IntlA11y/A11yFoundation/index.md)。
