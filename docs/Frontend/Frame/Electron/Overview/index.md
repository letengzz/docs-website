# Electron 概述

Electron 是一个**跨平台桌面应用**开发框架，开发者可以使用 HTML、CSS、JavaScript 等 Web 技术来构建桌面应用程序。它的本质是结合了 Chromium 和 Node.js，现在广泛用于桌面应用程序开发。

**官方网站**：https://www.electronjs.org/zh/

例如这些桌面应用都用到了 Electron 技术：

- Visual Studio Code
- GitHub Desktop
- 1Password
- 新版 QQ
- Discord
- Slack
- Figma Desktop

## Electron 的优势

1. **跨平台**：同一套代码可以构建出能在 Windows、macOS、Linux 上运行的应用程序。
2. **上手容易**：使用 Web 技术就可以轻松完成开发桌面应用程序。
3. **底层权限**：允许应用程序访问文件系统、操作系统等底层功能，从而实现复杂的系统交互。
4. **社区支持**：拥有一个庞大且活跃的社区，开发者可以轻松找到文档、教程和开源库。
5. **自动更新**：内置自动更新机制，方便应用版本管理。
6. **原生 API 集成**：支持系统通知、剪贴板、对话框等原生功能。

## 核心概念

### 主进程（Main Process）

- 每个 Electron 应用只有一个主进程
- 负责创建和管理渲染进程
- 可以访问 Node.js API 和原生系统功能
- 使用 `BrowserWindow` 创建和管理窗口

### 渲染进程（Renderer Process）

- 每个 `BrowserWindow` 实例对应一个渲染进程
- 运行在 Chromium 环境中
- 负责渲染页面和处理用户交互
- 默认无法直接访问 Node.js API

### 预加载脚本（Preload Script）

- 在渲染进程加载网页之前执行
- 可以访问 Node.js API
- 通过 `contextBridge` 安全地向渲染进程暴露 API
- 是主进程和渲染进程之间的桥梁

## 适用场景

- 需要跨平台的桌面应用
- 团队熟悉 Web 技术栈
- 需要集成 Web 服务和 API 的应用
- 需要访问系统底层功能的应用

## 不适用场景

- 对性能要求极高的应用（如游戏）
- 对安装包大小有严格限制的应用
- 需要深度系统集成且性能敏感的应用

## 版本信息

Electron 跟随 Chromium 快速迭代，大版本发布节奏约为**每 8 周一个**，并采用「**最近三个大版本**」的支持策略：进入稳定线后就只对这三个版本提供安全修复。

| 大版本 | 发布时间 | Node.js | Chromium | V8 |
| --- | --- | --- | --- | --- |
| 43.x | 2026-07 | 24.x | 150 | 15.0 |
| 42.x | 2026-05 | 24.x | 148 | 14.8 |
| 41.x | 2026-03 | 24.x | 146 | 14.6 |

::: tip 建议
建议使用**最新的稳定大版本**，以获得最佳的安全性与性能。Electron 的每次大版本升级都包含大量 Chromium 安全修复，长期停留在旧版本是桌面应用最容易被忽略的风险。

选择升级目标时，优先挑「当前稳定线」而不是 beta / nightly；升级前先跑通 [自动化测试](../Testing/index.md) 并核对 [安全基线](../Security/index.md)。
:::

### 近期值得关注的版本变化

| 版本 | 变化 | 影响 |
| --- | --- | --- |
| 43.x | 主进程从内嵌 Node 启动快照启动、框架包与预加载脚本以编译后的 V8 字节码缓存 | **启动性能提升**，预加载脚本堆栈能正确显示路径与行号 |
| 42.x | 改为**首次运行 bin 脚本时动态下载二进制**，不再依赖 `postinstall` | 供应链安全增强，同时支持 `npm install --ignore-scripts` |
| 41.x | macOS 支持为 ASAR 嵌入**完整性摘要**并在启动时校验；支持 MSIX 自动更新 | 完整性检测与 Windows 更新方式扩展 |
| — | 官方已宣布**停止支持 32 位平台** | 存量 32 位项目需规划迁移到 64 位 |

::: warning 说明
上面的版本号、日期与组件对应关系以官方发布说明为准，会随新版本发布而变化。**升级前请查阅当前官方文档确认目标版本的具体要求**。
:::
