## 与「构建缓存与可复现构建」专题的分工（第 199 天补充）

本目录回答的是「**这一次构建怎么描述出来**」：生命周期有哪几个阶段、依赖怎么解与怎么冲突、多模块怎么组织、构建脚本怎么写。它不回答「**第二次构建能不能不算**」——那是另一个问题，键与环境都不一样。

| 问题 | 本目录 | [构建缓存与可复现构建](../BuildCache/index.md) |
| --- | --- | --- |
| 生命周期阶段（`validate → compile → test`） | 讲 | 只当作「任务的边界」引用 |
| 依赖解析与冲突调解 | 讲 | 只把解析结果（lockfile）当成**指纹的一个输入** |
| `--offline` / 本地仓库 | 讲（依赖缓存层） | 明确区分：这属于**依赖缓存**，与任务级缓存不是一回事 |
| build cache 开关 | 只提一句 | 整页展开：键、淘汰、远程、假命中、可复现 |

一个容易混的点先在这里说清：**`~/.m2` 与 `~/.gradle/caches/modules-2` 存在，不代表构建有缓存**。它们缓存的是「依赖包」；改一行源码仍然要从头编译。任务级缓存（Gradle 的 `org.gradle.caching=true`、Turborepo 的本地 `.turbo/cache`）缓存的才是「编译结果」，两者失效半径与收益完全不同，混谈就会得出「我明明有缓存，为什么还是慢」。
