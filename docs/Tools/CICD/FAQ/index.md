# CI/CD 常见问题与最佳实践

本页汇总 CI/CD 落地中最常踩的坑：流水线跑不通、环境不一致、部署失败、回滚失效、安全泄露、速度太慢等，并给出排查路径与生产级最佳实践清单。

## 流水线一直失败，怎么排查

按顺序检查：

```text
语法 → 环境 → 依赖 → 测试 → 权限 → 网络
```

1. **语法错误**：本地校验 YAML（GitHub Actions 可先 `act` 本地模拟；GitLab 用 CI Lint；Jenkins 用 pipeline validator）。
2. **环境不一致**：本地能过 CI 挂，检查 Node/Maven/JDK 版本、换行符、大小写文件系统。
3. **依赖安装失败**：看是否网络受限（内网源）、lock 文件过期、缓存损坏。
4. **测试不稳定**：随机失败看是不是 Flaky Test（并发/时序/外部依赖）。
5. **权限不足**：密钥缺失、Runner 无 Docker 权限、制品库登录失败。

## 构建通过但测试不跑/不生效

1. 确认测试命令真的执行（看日志里的测试数量）。
2. 单元测试被 `skipTests` 跳过：检查 CI 命令与 Maven/Gradle 配置。
3. 覆盖率报告路径不对：报告没上传或 JaCoCo 未绑定 verify 阶段。
4. 测试连接了不存在的服务：集成测试需要 `services`/Testcontainers。

## 部署成功但服务起不来

```text
症状：流水线绿了，用户访问 502
```

1. **镜像启动失败**：本地 `docker run` 复现，看启动日志（缺环境变量？配置指向错误？）。
2. **健康检查没做**：部署完没有探活，服务 CrashLoop 也没人知道。
3. **配置漂移**：prod 配置与 staging 不一致（数据库地址、密钥）。
4. **端口/网络不通**：Service selector 与 Pod label 不匹配。
5. **资源不足**：内存/CPU limit 太低，进程被 OOM Kill。

对策：部署后强制健康检查 + 失败自动回滚（见 [自动部署与回滚](../DeployRollback/index.md)）。

## 回滚失效的常见原因

| 原因 | 说明 |
| --- | --- |
| 镜像 Tag 被覆盖 | `latest` 或重复 Tag 指向了别的内容；用不可变 Tag |
| 数据库已变更 | 旧代码不兼容新表结构；迁移先行、向前兼容 |
| 配置不可回退 | 配置中心改了不随部署回滚；配置与应用版本联动 |
| 制品已被清理 | 保留策略太激进，旧制品没了；保留最近 N 个 |
| 手工修改线上 | 集群状态被手工改过，回滚命令失效；杜绝手工改 |

## 流水线太慢，怎么提速

先量化再优化：

1. 用耗时报告找出最慢阶段（下载依赖？编译？E2E？）。
2. 依赖缓存（npm ci --cache / ~/.m2）。
3. 并行化：同阶段 Job 并行、测试分片。
4. 路径过滤：只跑受影响模块。
5. 更快的 Runner：更大规格、SSD、就近区域。
6. 全量测试移到夜间/发布流水线。

## 密钥泄露了怎么办

```text
发现 Token/密码进了 Git 历史
```

1. **立即吊销**：去对应平台撤销/重置该密钥。
2. **清理历史**：用 `git filter-repo` 或 BFG 清除历史中的密钥（重写历史需团队协调）。
3. **轮换所有引用**：凡使用过该密钥的地方全部换新。
4. **加扫描防线**：接入 Gitleaks/trufflehog 到流水线，阻止再犯。
5. **团队复盘**：密钥为什么进代码库，补上流程与工具。

## 本地能跑，CI 挂掉的经典差异

| 差异 | 对策 |
| --- | --- |
| 大小写敏感文件系统 | 统一文件名大小写；CI 用 Linux |
| 换行符 CRLF/LF | `.gitattributes` 统一 `text eol=lf` |
| 时区 | 测试断言用 UTC，避免依赖本地时间 |
| 环境变量缺失 | 所有环境变量在 CI 显式声明（含默认值） |
| 依赖版本漂移 | lock 文件 + 固定版本 |
| 随机端口冲突 | 测试用随机端口或 Testcontainers 隔离 |
| 内存/磁盘限制 | CI 机器小规格跑不动，调大规格或优化资源占用 |

## 企业落地最佳实践清单

::: tip CI/CD 十二条军规
1. 提交流水线 10 分钟内完成，超时就拆。
2. 每次提交都自动构建 + 单元测试 + Lint。
3. MR 合并前 CI 必须通过（硬性门禁）。
4. 质量门禁：新增覆盖率 ≥ 80%、无新增 Bug/漏洞。
5. 制品不可变：版本 = 语义化版本 + 构建号 + commit SHA。
6. dev/staging/prod 使用同一个制品，禁止分别构建。
7. 生产部署默认人工确认，发布记录留痕。
8. 部署后健康检查，失败自动回滚。
9. 密钥全部进平台密钥库，流水线文件零密钥。
10. 依赖与镜像入库前安全扫描。
11. 配置变更也走 MR + 评审，与应用同版本管理。
12. 定期故障演练：CI 宕机、制品库故障、回滚演练。
:::

## 验证方式

1. 对照「十二条军规」给自己的流水线逐条打分，标记差距项。
2. 做一次“密钥泄露”演练：确认吊销流程与扫描防线有效。
3. 做一次“部署失败”演练：确认自动回滚与通知全流程。
4. 用耗时报告优化一个最慢阶段，量化前后耗时对比。
