# 已知缺陷与豁免登记

> 用途：验收清单 **A3「已知缺陷有登记与豁免说明」** 的判据文件。
> 判据不是「有没有这个文件」，而是「**每条遗留缺陷都写明了影响、规避方式、豁免人**」。
> 没有任何一条遗留缺陷、且表里确实一片空白的项目，同样要说明「为什么可以空」。

| KI-001 | `GET /actuator/env` 在非 `prod` 环境未做字段脱敏，`spring.datasource.password` 以 `******` 呈现但键名可见 | 仅非生产环境；生产环境该端点已由 `management.endpoints.web.exposure.include` 关闭 | 生产环境不暴露该端点；预发环境仅限内网访问 | 安全负责人 · 张（2026-09-25） | 1.3.0 |

每条必须能回答三个问题，缺一条就不算登记完成：

1. **谁能碰到它** —— 只在内网？只在预发？还是所有用户？（「影响面」列）
2. **怎么绕开** —— 规避方式必须是**可执行的动作**，不是「注意一下」。
3. **谁认这个账** —— 豁免人要有姓名与日期。没有豁免人的遗留缺陷等于没人认领。

## 2. 什么样的条目**不算**已知缺陷

把下面这些塞进登记表，是让登记表失效的最快方式 —— 它们要么不是缺陷，要么不该被豁免：

- **待办功能**（「还没做导出」）→ 属于需求，进需求池，不进缺陷登记表。
- **「偶现、无法复现」** → 先补监控与日志，能复现之后再登记；否则登记表会变成垃圾桶。
- **「性能可以更好」** → 属于优化项，除非它已经越过验收阈值，否则不进这张表。
- **没有豁免人的条目** → 没人认账的豁免等于默认通过，等于没有门禁。

## 3. 豁免的时效

| 级别 | 允许存在的时长 | 到期处理 |
| --- | --- | --- |
| 安全类（如 KI-001） | 一个发布周期 | 到期未修则**阻塞下一个版本发布** |
| 数据一致性类（如 KI-002） | 两个发布周期 | 到期未修则升级到负责人评审 |
| 工程效率类（如 KI-003） | 不限，但每次发布要在发布说明中列出 | 连续两次发布未动则重新评估优先级 |

## 4. 与其他交付物的对应

- **验收清单**：`python Acceptance/acceptance_check.py` 的 **A3** 项会检查本文件存在且非空
  （≥300 字节）；`--strict` 下 A3 属于 AUTO 项，**不接受人工签名绕过**。
- **回滚计划**：`rollback_plan.md` 里的触发阈值若被某个已知缺陷影响，必须在两处同时更新。
- **用例矩阵**：矩阵里标 `?`（待补）的格子若因已知缺陷而长期无法覆盖，应在「影响面」列写明。
