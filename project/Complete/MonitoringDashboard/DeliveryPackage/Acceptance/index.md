# 上线验收清单

**读者要做的动作：拿这张表逐条勾，勾不完不许交付。每条只勾三种状态之一——`通过`（附命令与实测值）、`不适用`（附理由）、`未通过`（附卡住的位置）。**

![上线验收清单：六层 24 项，每一层都有自己的证据形态](../../assets/acceptance-checklist.svg)

::: tip 一句话定位
**24 项 ≠ 30 条命令。** 每一项要回答的是「用什么证据证明它成立」，命令只是拿证据的手段；说不出证据形态的那一项，说明它还不是判据。
:::

**证据分三类**（表里用符号标出）：`主` 主读数（命令直接给出的数字/集合）、`旁` 旁证（另一条独立路径得到同一结论）、`档` 文档级（核对配置或文档里的一个事实）。

## 第 1 层 · 容器与幂等（4 项）

- [ ] `1-1` 【主】三个服务全部 `running`：<span v-pre>`docker compose ps --format '{{.Service}} {{.Status}}'`</span>
- [ ] `1-2` 【主】再次 `up -d` 三行全为 `Running`，**无一行 `Recreated`**（幂等）
- [ ] `1-3` 【旁】二次 `up -d` 之后历史数据仍在：`count(prometheus_tsdb_head_series) > 0`
- [ ] `1-4` 【档】编排文件成对声明：`compose.yaml` 与 `compose.singlefile.yaml` 的服务集合一致

## 第 2 层 · 文件一致性（4 项）

- [ ] `2-1` 【主】6 个配置文件的宿主 / 容器内 sha256 前 16 位逐条相等
- [ ] `2-2` 【主】`promtool check config prometheus/prometheus.yaml` → `SUCCESS`
- [ ] `2-3` 【主】`promtool check rules` 两份规则 → `SUCCESS: 3 rules` 与 `SUCCESS: 6 rules`
- [ ] `2-4` 【档】关键挂载为只读（`:ro`），容器内无写入点

## 第 3 层 · 采集与规则（4 项）

- [ ] `3-1` 【主】`activeTargets` 数量 = 5，且全部 `up`；`unknown` = 0
- [ ] `3-2` 【主】`activeAlertmanagers` = 1，`droppedAlertmanagers` = 0
- [ ] `3-3` 【旁】告警规则**按名字集合**比对（不是只比条数）
- [ ] `3-4` 【档】三组抓取间隔与配置文件里的值逐条一致

## 第 4 层 · 大盘数据源（4 项）

- [ ] `4-1` 【主】`D1 有序列`：每张大盘 `count(<选择器>) > 0`
- [ ] `4-2` 【主】`D2 三态可分`：`总数 = NaN + 零值 + 非零`，三者相加回到总数
- [ ] `4-3` 【主】`D3 值可解释`：每个 `count(...)` 都配了 `or vector(0)`
- [ ] `4-4` 【档】三张大盘各自记录「本次读数」与「是否为空面板」

## 第 5 层 · 自监控（4 项）

- [ ] `5-1` 【主】自采集目标数为 **1**（Prometheus 抓自己不是冗余）
- [ ] `5-2` 【主】规则评估失败数为 **0**
- [ ] `5-3` 【主】单次抓取耗时与 15 分钟峰值各记一个数，并与阈值比对
- [ ] `5-4` 【档】保留策略的时间与体积双上限都在配置里声明

## 第 6 层 · 保留与告警端到端（4 项）

- [ ] `6-1` 【主】保留上限在**四个位置**读到同一件事：编排文件声明 → 容器 `Args` → `/-/status/flags` 回显 → 运行期回读为字节数
- [ ] `6-2` 【主】告警端到端响过一次，且通知条数等于**分组数**（不随实例数增长）
- [ ] `6-3` 【旁】被抑制的告警留下 `inhibitedBy` 记录
- [ ] `6-4` 【档】每条告警都有 `runbook_url`，且指向的章节存在

## 怎么填「不等于 0」的那几项

| 情形 | 正确填法 | 错误填法 |
| --- | --- | --- |
| 靶服务无流量，错误率为 `0` | `通过`，并注明「`0` 是正确状态：静态靶无流量」 | 填 `不适用`（它不是不适用，是恰好为 0） |
| 需要真实通知渠道的项 | `未通过`，附「前置：真实凭据」，并登记解除条件 | 填 `通过`（**不许把期望值抄进实测列**） |
| 需要容器运行时的项 | 在无运行时的环境里填 `未通过`，原因写「本机无容器运行时」 | 填 `不适用`（它适用，只是今天跑不了） |

::: danger 注意：三条会让这份清单失效的填法
1. **把期望值抄进实测列**（「预期 6 条，实测：6 条」）——这不是读数，是复述题目。
2. **把「不适用」当逃生门**——不适用必须有客观理由（该能力不存在于本交付），不是「今天没空跑」。
3. **只勾不附证据**——不附命令与实测值的勾，等价于没勾。
:::
