# 从零复现指南

**读者要做的动作：按 0 → 5 的顺序执行。每一步之后停一下，核对「应该看到什么」；对不上就停在第几步，不要往下走——后面每一步都依赖前面那一步是真的通的。**

![从零复现：六个步骤的顺序与每一步的停点](../../assets/reproduce-steps.svg)

## 0. 前置检查（必须先跑，不许跳过）

```shell
bash scripts/preflight.sh; echo "退出码=$?"
```

| 退出码 | 含义 | 你要做的 |
| --- | --- | --- |
| `0` | 前置齐备，可以继续 | 往下走第 1 步 |
| `1` | 前置齐备，但检查未通过（缺端口 / 缺文件 / 缺卷） | 按脚本输出逐条修，修完重跑 |
| `2` | 前置缺失到无法判定（连判定所需的东西都没有） | 先装容器运行时，再重跑 |

**最容易犯的错：把 `1` 当成「警告」继续往下走。** `1` 的意思是「检查跑起来了，并且没通过」。

## 1. 起栈

```shell
bash bin/one-click-up.sh; echo "退出码=$?"
```

应该看到三级就绪信号依次出现，最后一行是退出码 `0`。**三张大盘此时还不一定有数据**——靶服务需要被访问过才会产生指标。

## 2. 产生流量

```shell
for i in $(seq 1 50); do curl -s -o /dev/null "http://localhost:8088/work?n=$i"; done
```

应该看到：50 次请求全部返回 2xx。**没有这一步，第 3 步会看到空面板**——这不是故障，是缺流量。

## 3. 看三张大盘

打开 `http://localhost:3000`，依次点名三张：

| 大盘 | 应该看到 | 看到空白的含义 |
| --- | --- | --- |
| 请求总览 | 请求速率曲线随时间上升 | 抓取没生效（回第 0 步看第 4 项） |
| 错误率 | 有一条曲线，值可能为 `0` | **全空**是抓取问题；值为 `0` 是正常的 |
| 资源水位 | 进程内存 / CPU 曲线 | 靶服务没起来 |

::: danger 注意：「空面板」与「值为 0」是两件事
`0` 是一个**读数**，空白是**没有读数**。前者说明链路通、指标存在、当前没有错误；后者说明链路断在某一段。把两者混为一谈，会让你在正确状态下排障、在真正的故障上放行。
:::

## 4. 核对告警链路

```shell
curl -s http://localhost:9093/api/v2/status | head -5
curl -s http://localhost:9090/api/v1/rules | grep -c '"name"'
```

第一条应有 JSON 返回；第二条的计数应等于告警规则条数（本工程为 **6**）。

**期望「响一次」的话**：临时把靶服务停掉 2 分钟，`TargetDown` 会进入 pending 并最终 firing。**不要在交付验收时做这件事**——验收要的是当前状态可读，不是制造一次告警。

## 5. 收尾自查

```shell
bash scripts/check-panels.sh; echo "退出码=$?"
docker compose ps --format '{{.Service}} {{.Status}}'
```

应该看到：`check-panels.sh` 对三张大盘各输出一行结论（有序列 / 三态可分 / 值可解释）；`docker compose ps` 三个服务都是 `running`，**没有一行是 `Recreated`**（后者说明不是幂等重启）。

## 附：与「一键起」的关系

**本指南 = 动作顺序**（做什么、看到什么、什么时候停）；[一键起与大盘可用性](../../OneClickUp/index.md) **= 判据**（三级就绪为什么这么定、五层验收怎么回填）。本指南不复制配置内容——`compose.yaml`、`prometheus.yaml`、`bin/one-click-up.sh` 的完整内容在各自主题页，见[交付包台账](../index.md)第四节。
